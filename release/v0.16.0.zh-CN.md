# Xynigo Sourcing v0.16.0 物流查询可靠性与桌面策略测试版

v0.16.0 是一次内部测试阶段的次版本升级，集中解决大批量物流查询中的 HubStudio Local API 短暂断连、资源不足、环境关闭延迟和界面反馈问题，并将查询高级设置统一迁移到本地执行器。

## 主要变化

- HubStudio Local API 的连接失败、响应超时、系统资源不足和浏览器启动冲突采用统一分类与恢复策略。
- `startBrowser` 超时后先回读真实环境状态；确认未启动时只允许一次安全重试，避免重复打开同一环境。
- 查询完成后精确确认目标环境已经关闭；资源恢复后逐步恢复配置并发，不因一次压力永久降速。
- 物流查询复用六小时完整环境库存缓存。缓存完整且新鲜时直接下发所选环境映射，缺失或过期时自动回退本机实时查询。
- 新建、补建或重试环境完成后主动失效本机环境缓存，查询缺号时强制刷新一次，避免使用旧映射。
- 查询范围区域固定为稳定栅格，消除长提示造成的页面漂移。
- “等待上一环境完全关闭”与正常查询进度交替展示，明确任务仍在继续。
- 超长 HubStudio 错误改为短摘要加详情弹窗，不再撑宽查询结果表格。
- 物流查询高级设置完整迁移到 Windows/macOS 桌面客户端；网页只展示所选执行器当前策略，不再允许临时覆盖。
- 浏览器模式与“允许连接已打开环境（只读）”由执行器本机统一管理，历史重查、单行重查和异常批量重查遵循同一策略。
- 插件及相关界面名称统一为“店小秘提单助手”。

## 升级说明

- 云端数据库迁移 head 仍为 `0028_hub_environment_cache`，本版本不新增数据库迁移。
- 物流高级设置和完整的 Local API 恢复策略需要升级到 v0.16.0 本地执行器。
- 旧执行器未上报“允许连接已打开环境”时默认关闭该选项，避免误连采购人员正在操作的环境。
- 发布后建议分别在 Windows 与 macOS 验证桌面设置保存、在线更新和 100 个环境物流查询。

## 测试边界

- 当前安装包继续使用内部 `test` 通道；Windows Authenticode 与 macOS Developer ID 公证门槛仅在 `stable` 通道强制执行。
- 线上环境仍为共享隔离测试实例，不包含生产数据库、生产凭证或生产飞书数据。
