# Xynigo Sourcing v0.17.3 抽检与订单状态修复

v0.17.3 修复桌面抽检数设为 1 却检测整批环境的问题，并交付订单状态和默认数据源切换修复。

## 主要变化

- 创建绑号、备用和测试环境时，以执行器桌面设置的抽检数为准；0 表示不抽检，1 表示最多检测 1 个成功环境。网页旧参数无法覆盖，运行中修改设置不影响本轮。
- 单行或批量重试只抽检本轮成功修复的环境，数量不足时按实际成功数封顶。
- 出口 IP 检测实时同步计划数、完成数和国家匹配数，修复检测中显示 30/30、顶部仍为 0/0 的问题；旧任务计划未知时明确提示。
- 修复 SHEIN 墨西哥站 `Esperando ser enviado` 被误判为“已发货”；尚未发货的订单保持待发货状态，不凭状态文案推断物流号存在。
- 桌面客户端支持在个人速填表与团队默认表之间切换。管理员可调整采购员默认映射，普通采购员可调整自己的默认数据源；切换团队默认后清除个人覆盖。
- CI 改为执行本地 pytest 全量用例，覆盖既有 unittest 与新增函数测试；新增 Python 3.12 云端完整回归，并为 Web 行为测试显式配置 Node.js。
- 修复 Windows 卸载后遗留 Python 进程锁住运行目录的问题；只停止本安装目录所属进程，保留用户配置和运行数据。

## 升级说明

- 云端与 Windows/macOS 执行器配套升级后，完整获得抽检配置与进度修复。旧执行器需要通过桌面检查更新安装新版。
- 数据库保持 `0030_logistics_auto_site`，本版本不新增迁移。
- 已结束的旧查询历史不会自动改写；订单状态需使用新版执行器重查。
- 发布后应验证桌面抽检数 1 的建环境批次、待发货订单状态及个人/团队数据源切换。

## 测试通道

沿用内部 `test` 通道和现有共享隔离测试实例。Windows 与 macOS 安装包沿用现有签名状态，不提升为已签名生产发行版。
