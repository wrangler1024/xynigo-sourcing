# Xynigo Sourcing v0.17.2 物流查询可靠性补丁版

v0.17.2 是内部测试通道补丁版本，集中修复跨电脑物流查询、HubStudio 浏览器内核识别和查询页面操作区问题，并统一调整 Windows 与 macOS 桌面客户端窗口比例。

## 主要变化

- 物流查询改为按每个 HubStudio 环境自动识别美国站或墨西哥站；序号输入不再依赖网页选择的站点或分组，混合站点环境可在同一批次中安全路由。
- HubStudio 分组降级为可选的序号导入工具，不再决定查询站点或限制序号查找范围。
- 云端查询操作栏移除“高级设置”和当前查询 ID；高级策略继续在桌面执行器管理，稳定查询 ID 仍保留在查询历史与历史详情中。
- 兼容 HubStudio 3.58 的 `code=-1` 中文内核缺失响应；识别到 Chrome 150 等缺失版本后，桌面诊断页会显示“下载并修复”入口。
- SHEIN 登录态不再仅凭一次 URL 跳转判断；系统会同时检查可见登录界面并二次导航确认，减少环境跨电脑归档切换期间的瞬时误判。
- Windows 默认窗口调整为 1240×840，macOS 内容区调整为 1240×812，两端外框均接近现场确认的 1.47:1 比例。
- 新增 `logistics.auto-site.v1` 执行器能力门禁；旧执行器不能领取自动站点任务，并会收到明确升级提示。

## 升级说明

- 云端数据库迁移到唯一 head `0030_logistics_auto_site`，允许物流查询批次保存 `AUTO` 路由模式。
- 云端服务与本地执行器需要同时升级到 v0.17.2；旧执行器不会执行新的自动站点批次。
- 部署时先备份 PostgreSQL，再执行 Alembic 迁移；共享测试只重建认证服务，不重启或重建数据库容器。

## 测试边界

- 本地完整测试、云端自动站点/查询历史/执行器通道测试以及双平台启动器编译检查均在发布前执行。
- Windows 与 macOS 安装包继续使用内部 `test` 通道，尚未完成 Authenticode、Developer ID 签名与公证。
- 线上环境仍为共享隔离测试实例，不包含生产数据库、生产凭证或生产飞书数据。
