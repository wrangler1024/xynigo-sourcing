# 建环境任务中断保护与恢复

适用版本：v0.17.14。适用于买家号绑号环境批次。

## 客户端退出保护

任务受理、执行、结果回传期间，执行器拒绝退出或重启，返回 `409 executor_tasks_active`。退出许可与新任务受理互斥，避免检查完空闲后又收到任务。Windows、macOS 启动器收到明确的空闲退出许可后才结束进程；请求超时、拒绝或状态不明时保留后台任务。重新打开客户端接管旧会话也遵守此规则。

采购助手连接异常时先使用插件“重新检测”。任务进行中不要通过结束进程、关机等方式重新连接；这些操作无法由应用内退出保护拦截。

## 中断后的页面表现

执行器启动任务后租约过期，云端保留 `uncertain` 状态和 `lease_expired_after_start` 原因。页面显示已确认完成数与未确认完成数，不再把“已创建但未完成绑号”的环境算作新建完成。

云端恢复清单合并原批次历次结果和预留的环境身份。即使第一条进度尚未上报，也能保留待核对账号。

## 核对并续跑原批次

1. 原创建人升级原采购电脑的客户端，并保持 HubStudio、执行器运行。
2. 在“创建历史”找到中断批次，点击“载入原批次”。
3. 选择原采购电脑，按原站点、分组上传原始 xlsx；混合 Cookie 和文件名冲突仍需明确确认。
4. 点击“核对并续跑原批次”，确认原任务已停止。
5. 查看逐行结果。续跑沿用原任务链、环境名称和采购员分配，成功行不重新创建。

续跑前必须重新读取 HubStudio 完整环境列表。已有环境按原环境名称、环境 ID、号商单号以及可确认的完成步骤核对：

| 核对结果 | 处理 |
| --- | --- |
| 已完整完成且身份匹配 | 跳过，计为恢复已有 |
| 绑号完成有云端或原电脑脱敏检查点证明，环境已关闭，缺少备注 | 只补备注，不重复绑号 |
| 环境已存在但绑号结果未知 | 保留原环境，提示人工核对 |
| 原环境 ID 丢失、变化、被移到其他分组，或有冲突备注 | 阻止该行写入并提示原因 |
| 同名环境不唯一、原账号清单不一致 | 整批预检失败，不写入 |
| 全量核对确认不存在，且没有历史环境 ID | 创建前再查询同名环境，通过后继续创建 |

恢复期间停止并撤销，只撤销本次尝试新建的环境，不删除之前尝试留下的环境。已有环境的身份或绑定证据不充分时，不以自动重建消除异常。

## 发布与验证

- 先发布识别 `environment.resume.v1` 的云端接口，再升级采购电脑客户端。仅更新网页不能给旧客户端增加退出保护或恢复能力。
- 新能力沿用现有 Run、加密执行计划、账号互斥及幂等机制，无新增数据库表。
- 专项回归覆盖：未收到第一条进度、租约过期、整批与部分进度、最终结果回传失败、拒绝退出、恢复已有、未创建行、绑定证据不足、错文件/站点/设备/创建人、重复提交及回滚范围。
- 所有写入链路测试使用合成账号和模拟 HubStudio；真实采购电脑仍需升级后进行现场验收。
