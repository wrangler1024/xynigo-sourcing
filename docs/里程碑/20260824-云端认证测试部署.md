# 20260824 云端认证测试部署

## 结论

Xynigo 云端认证服务已在腾讯轻量服务器形成可访问、可恢复的隔离测试实例。测试地址为 `https://xynigo.samforo.icu`，本地采购服务和现有外部服务没有切换到该实例。

## 已验证

- Docker Compose 构建成功，PostgreSQL、一次性迁移容器和认证服务按依赖顺序启动。
- `/healthz`、`/readyz` 均通过 HTTPS 返回 200；未登录访问 `/v1/auth/me` 返回 401。
- 飞书登录入口 `/v1/auth/feishu/start` 已切换至“小犀代采”，真实授权回调返回 303，随后 `/v1/auth/me` 返回 200。
- 首位已验证企业用户已从 `pending` 激活为 `active`，获得 `super_admin` 角色；初始目录为 11 项权限，模块入口目录扩展后由后端自动补齐为 17 项。会话摘要与成功/拒绝审计均已落库。
- PostgreSQL 已执行 `0001_identity_foundation` 和 `0002_local_login_bridge`，public schema 为 10 张业务表加 `alembic_version`，共 11 张表。
- PostgreSQL 不发布宿主机端口；认证服务只绑定 `127.0.0.1:8080`。
- Nginx 提供 HTTP 到 HTTPS 重定向、TLS 1.2/1.3、HSTS 和基础安全响应头。
- Let's Encrypt 证书当前有效期至 2026-11-22，系统已有自动续期任务。
- root-only 数据库备份能够恢复到临时数据库，表数和迁移版本一致；临时数据库已删除。
- PostgreSQL 与认证容器重启后能够恢复就绪，迁移与表结构保持不变。
- `/v1/admin/*` 管理员 API 已在不新增迁移的前提下部署；未登录访问返回 401，OpenAPI 保留全部旧登录路由并包含 17 个管理员操作，其中包括自定义角色生命周期和手机号新增成员的解析/确认接口。
- 新增本地 8769 开发实例完成超级管理员只读联调，成员、角色、权限策略和有效会话均能通过本地安全代理读取，浏览器不接触 Bearer 会话。
- 权限目录新增工作台、采购中心、运营中心、财务中心、小犀助手和数据分析六项一级入口权限；目录同步后 `super_admin` 为 17 项，自定义角色与默认 `member` 未被自动授权。入口权限不代表相应规划功能或数据范围已经开发。
- 成员管理已增加按飞书绑定手机号精确查找并新增待审批成员。手机号不写入 Xynigo 数据库、响应或审计，确认接口会重新向飞书解析；预分配角色仍受独立角色管理权限与授权上限裁决。云端 26 项合成测试已覆盖该流程。
- 本地 8771 浏览器先验证缺少飞书权限时的明确提示与表单清理；权限、通讯录数据范围和应用可用范围发布生效后，真实查找成功返回指定普通企业成员的姓名、头像和激活状态。随后取消表单，成员仍为 1 人且控制台无 error；未写入真实成员。
- 2026-08-25 部署登录完成页自动关闭：云端页面使用 CSP SHA-256 固定脚本自行关闭，本地主页面成功领取会话后再次关闭命名授权窗口。真实弹窗语义验收后完成页自动消失，主页面保留；直接手动访问时保留手动关闭兜底。
- 2026-08-25 部署运营采购基础：迁移升级为 `0003_purchase_request_foundation`，新增采购三表、3 项采购权限和草稿/正式提交/读取 API；目录为超级管理员 28/28、管理员 25/28、成员 0/28。旧库目录升级时发现并修复同一请求重复插入角色权限的缺陷，新增回归后云端 33 项通过；采购三表保持 0 条，未写真实 Base。

## 当前状态

“小犀代采”飞书应用的安全设置已添加以下精确回调 URL：

```text
https://xynigo.samforo.icu/v1/auth/feishu/callback
```

云端测试环境已使用“小犀代采”的 App ID/App Secret，不再使用 `samforo-cli`。应用凭证只存在 macOS 钥匙串与服务器 root-only `.env`，切换过程未把 App Secret 写入命令参数、仓库或日志。

真实登录闭环已验证：飞书授权、令牌交换、用户信息读取、待审核保护、超级管理员白名单激活、会话 Cookie、`/v1/auth/me` 权限摘要和审计落库均正常。随后已增加本地一次性登录桥；本地 Python 服务通过高熵轮询令牌单次换取 Bearer 会话，并保存到系统安全存储。本地页面的登录、当前成员、权限摘要和退出撤销也已完成真实验证。直接展示云端回调页曾受应用内浏览器客户端策略影响，因此验收应结合本地页面状态、云端会话/审计记录和自动化测试，不以回调页最终展示作为唯一成功判据。

飞书当前对该应用的授权端没有登记 PKCE challenge：S256 与 plain 均在令牌端返回 `20049`。当前实例依照飞书 OAuth v3 的可选参数规则，受控设置为 `XYNIGO_AUTH_FEISHU_PKCE_METHOD=disabled`；仍保留 HTTPS、App Secret、精确回调、随机 `state`、state 摘要落库、5 分钟有效期和单次消费防重放。代码默认仍是 S256，后续飞书侧兼容后可通过环境变量恢复，无需改业务代码。

## 已知限制

- 当前是单机测试实例，没有高可用。
- 数据库备份仍在同机，尚未建立异机副本、保留周期和失败告警。
- 服务器访问 PyPI 较慢，首次镜像构建耗时较长；依赖未变化时可复用已缓存镜像层。
- 成员审批、角色授权、会话批量撤销和系统管理页面已部署并完成超级管理员只读联调；普通成员真实准入、权限限制和停用撤销闭环尚未验收。
- 云端登录已接入本地开发版，但尚未构建并灰度发布为正式采购绿色包；现有长期运行的采购实例不应被自动替换或停止。
- 当前部署暂时关闭 PKCE，需跟踪飞书 `20049` 兼容问题并在可用后恢复 S256。
- “小犀代采”应用最终成员可用范围和普通成员完整准入流程尚未形成真实验收记录。
- “小犀代采”的手机号解析最小权限、通讯录数据权限范围和应用可用范围已配置并通过真实查找验证。普通成员尚未确认新增、批准或登录；该飞书范围不等同于暂不开发的 Xynigo 业务数据范围功能。
