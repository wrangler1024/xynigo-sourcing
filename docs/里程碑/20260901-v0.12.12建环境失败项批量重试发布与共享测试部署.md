# v0.12.12 建环境失败项批量重试发布与共享测试部署

日期：2026-09-01

状态：共享测试已发布并部署，生产未部署

结论：在 v0.12.11 协作式安全停止基础上，买家号建环境已支持一次批量续跑当前全部失败行。批量操作不会选择完成、已停止、排队或运行中行，并且每行只从持久化断点中的第一个未完成步骤继续。该版本仍是内部 prerelease，不代表生产上线。

## 功能与安全语义

- 页面在批次存在失败行时显示“批量重试失败项（N）”，提交前明确二次确认范围。
- 服务端以执行瞬间的精确 `failed` 状态重新筛选目标行，不能由前端传入任意账号扩大范围。
- 每行复用 `completed_steps` 与原单行“重试此步”链路；已经完成的建环境、Cookie、绑号和备注步骤不会重复执行。
- 批量重试沿用 `envCreateWorkers` 实际并发，并在任务启动前统一预占所有目标环境名和已知 containerCode，继续遵守与物流查询的资源冲突闸门。
- 执行期间继续支持 v0.12.11 协作式安全停止：当前并发行完整收尾，尚未领取的失败行转为 `stopped`，不会在半行中强杀 HubStudio 写入。
- 云端工作台提交携带幂等键并锁定单行/批量按钮；响应中断后继续读取后台进度，不立即重复下发同一批任务。
- 云端结果回传只包含本次重试账号的脱敏结果；绑定映射清单在结束后重新生成。

## 主要实现

- `src/purchase_tool/env_batch.py`：新增 `BatchEnvOrchestrator.retry_failed()`，以原并发执行器运行失败行并复用断点、持久化和停止事件。
- `src/purchase_tool/main.py`：新增 `EnvBatchJob.retry_failed()` 与 `/api/envbatch/retry-failed`，负责凭证有效性、资源预占、任务生命周期、结果回传和摘要更新。
- `src/purchase_tool/web/index.html`：新增失败数量、批量确认、提交单飞锁、响应中断恢复和安全停止兼容交互。
- `cloud/auth-service/src/xynigo_auth/workspace_rpc.py`：新路由继续要求 `resource.environment.create` 权限。
- 云端与本机 Web 由同步脚本保持字节一致，没有维护第二份业务页面。

## 现场升级边界

部署后数据库回读两台执行器均已重新上线且 HubStudio 为 ready：新刚 Windows `DESKTOP-JG7FP2D` 仍为 v0.12.9，macOS `jeffdeMacBook-Pro.local` 仍为 v0.12.10。云端页面更新不等于本机能力更新：

1. Windows 在当前任务自然结束后，可从 v0.12.9 直接在线更新到 v0.12.12，不需要先安装 v0.12.10 或 v0.12.11。
2. macOS 使用 v0.12.12 标准 `.pkg` 覆盖安装，并核对上表 SHA-256。
3. 升级后先确认状态中心版本、设备在线和 HubStudio ready，再用脱敏小批量验证单行重试、安全停止和批量失败续跑。
4. 批量重试只能在失败根因已解除后人工触发；`stopped` 行仍通过重新选择相同原始 xlsx、保持站点/日期/分配不变来续跑。
5. 本次没有自动重跑任何现场建环境或物流任务，也没有部署生产环境。
