## 构建期发现并修复的问题

第一次候选构建中，CI 先构建 macOS 绿色包、再构建标准包。`scripts/update_release_assets.py` 只更新了 `platforms.macos-arm64`，却保留第一次构建写入的旧顶层兼容字段，导致同一 manifest 内新旧结构的 macOS 哈希不一致。

根因不是安装包本身，而是兼容旧更新器的顶层字段刷新条件错误：它只把 Windows 当作默认平台，没有处理“清单只有一个 macOS 平台”的独立构建场景。

修复后规则为：清单只有一个平台时，该平台同时刷新顶层兼容字段；多平台合并时仍由 Windows 维持旧版默认平台语义。新增回归测试覆盖同版本 Mac 包二次构建，防止以后再次出现“平台字段已更新、顶层字段仍旧”的隐性清单漂移。

4. 下一步必须在真实 Windows 采购电脑验证覆盖安装、配对和数据保留、状态中心、托盘、HubStudio、物流/买家号/建环境任务与在线更新；Mac 验证 Keychain、冻结运行时 CA、心跳和 workspace RPC。
