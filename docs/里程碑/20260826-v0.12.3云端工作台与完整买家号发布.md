## 踩坑经验

- PUBLIC 仓库不能直接推内部开发分支；从上一个公开标签创建净化分支，只复制可发布源码、测试和发行说明，并在创建标签前运行公开安全审计。
- 云端部署和本机绿色包更新是两条独立链路：页面刷新获得云端版本，本机执行器只能通过 GitHub Release 和用户确认升级。
- 旧 `xynigo-favicon.ico` 是犀牛吉祥物，并非部署前地址栏的 X；云端 `/favicon.ico` 必须别名到 `xynigo-x.ico`，同时提升查询版本清除浏览器缓存。
- `set -o pipefail` 下使用 `curl | grep -q` 可能因为 `grep` 提前退出让 `curl` 返回 23，从而触发错误回退；部署探针应先落临时文件再匹配。
- 部署验证不能依赖易变的页面文案；应验证标题、资产哈希、CSP、健康/就绪、登录状态和关键 API。
- 新公开工作树的云端测试要先执行 `uv sync --extra test`；裸 `uv run pytest` 可能因未安装 pytest 直接失败。
- Release 标签只能在净化分支 CI 六项任务全部通过后创建，避免失败版本被旧客户端 Latest API 自动发现。
