# 运营采购助手统一身份与正式提交基础

日期：2026-08-25

状态：云端采购基础与本机插件桥已部署；插件绿色包发布和真实飞书 Base 同步尚未执行。

## 目标

将店小秘运营采购助手从“浏览器手工配置本机服务 Token，直接写飞书测试 Base”调整为：

```text
店小秘扩展
  → Xynigo 本机安全桥
  → Xynigo 云端短期会话 + RBAC
  → PostgreSQL 采购单事实源 + 同步 Outbox
  → 飞书 Base 协同镜像
```

飞书 OAuth 只负责识别当前成员；飞书企业应用凭证、Base Token 和 Table ID 仍只能位于受信服务端，不能下发到插件。

## 已完成的本地增量

### 云端控制面

- 新增 `0003_purchase_request_foundation` 迁移：
  - `purchase_orders`：租户隔离的采购单、客户端快照、内容哈希、草稿版本、提交人/提交时间和同步状态。
  - `purchase_order_lines`：稳定 `lineKey=orderKey|lineNo`、有效标记和采购流程状态。
  - `purchase_sync_outbox`：`draft.saved` / `order.submitted` 两类去重同步事件。
- 新增三项权限：
  - `procurement.request.read`
  - `procurement.request.save`
  - `procurement.request.submit`
- 新增带 Bearer 会话和租户裁决的接口：
  - `POST /v1/purchase-orders/draft`
  - `POST /v1/purchase-orders/submit`
  - `POST /v1/purchase-orders/get`
- 草稿按不含客户端时间的规范化内容哈希幂等；已正式提交的单据不允许被变更草稿覆盖。
- 正式提交要求完整收件信息、至少一条明细、受信 SHEIN HTTPS 链接、`goodsId/skucode`、正指导价且采购数量等于销售数量。
- 正式提交人由云端已认证会话决定，浏览器不能伪造。审计事件只记内部采购单 ID、版本和结果，不记收件信息或飞书 Open ID。

### Xynigo 本机执行器

- 新增专用插件桥接端点：
  - `POST /api/extension/v1/pair/request`
  - `POST /api/extension/v1/status`
  - `POST /api/extension/v1/purchase-orders/draft`
  - `POST /api/extension/v1/purchase-orders/submit`
  - `POST /api/extension/v1/purchase-orders/get`
- 配对必须由已登录 Xynigo 成员在同源 `/extension-connect` 页面主动确认。
- 桥接令牌为进程内随机值，与 32 位 Chrome 扩展 ID 及 `chrome-extension://` Origin 绑定；重新配对会轮换令牌。
- 云端 Bearer 会话仍只保存在 macOS Keychain / Windows CurrentUser DPAPI，插件、店小秘页面和本机桥接响应都拿不到。
- 权限策略页已将三项采购单权限归入“采购中心 → 运营采购单”。云端测试实例目录已为 28 项：`super_admin=28/28`、`admin=25/28`、`member=0/28`。

### 店小秘扩展 `0.1.51`

- 删除弹窗中的本机服务地址和手工 Token 输入，改为“连接 Xynigo / 刷新状态”。
- 扩展只扫描 `127.0.0.1:8765-8779`，且只将采购请求发给用户确认后的 Xynigo 本机 Origin。
- “保存采购单”与“提交采购单”改用不同消息和服务端点；提交成功后明确显示“已正式提交”。
- 接口返回 `syncStatus=pending` 时，页面只显示 Xynigo 已保存/已提交，不再误报“飞书已同步”。
- 保持店小秘原生审核与备注完全解耦；浏览器本地仍仅缓存剔除收件信息的采购快照。

## 接口状态语义

| 字段 | 含义 |
|---|---|
| `submissionStatus=draft` | PostgreSQL 已保存可继续修改的草稿 |
| `submissionStatus=submitted` | 采购单已正式提交，当前版本锁定 |
| `syncStatus=pending` | 已写入同步 Outbox，飞书镜像尚未确认 |
| `syncStatus=synced` | 未来 Worker 写入并回读确认飞书镜像后才能设置 |
| `syncStatus=failed/conflict` | 飞书同步超过重试边界或发现重复键，需人工复核 |

## Web 采购中心 P0（已部署）

- 新增采购概览、采购单分页列表和采购单详情三条云端只读接口，并由本机 `/api/procurement/*` 安全代理给 Web 工作台。
- 三条接口统一校验 `procurement.request.read` 和 `tenant_id`；列表/概览不返回收件信息，详情返回主单与明细并记录敏感详情读取审计。
- 列表支持提交状态、同步状态、明细工作流状态组合筛选和 `page/pageSize` 分页；非法状态、页码和详情 UUID 由接口校验拒绝。
- 本机代理只允许三个采购中心读取路径，不允许跳转到管理接口、外部 URL 或路径穿越；云端 Bearer 会话继续不进入浏览器。
- 前端已把“采购任务”从规划入口升级为真实工作区页签，包含六项概览、三类状态筛选、分页列表和按需详情；“采购执行”和“异常协同”继续保持规划状态。
- 前端全局状态只保留安全列表摘要。详情未写入全局缓存，关闭详情会取消接收当前请求结果并清空详情 DOM。
- Playwright 使用 25 条脱敏合成采购单通过桌面布局、20/25 分页、草稿筛选、详情、可信 SHEIN 链接和关闭清空验证；未读取云端真实采购单。
- 本批没有新增表或迁移，没有修改测试实例中的已提交采购单，也没有执行飞书、店小秘审核或其他外部写入。
- 完整契约见 [`../采购中心接口-P0.md`](../采购中心接口-P0.md)。

2026-08-25 后续已将上述只读接口连同采购执行测试版部署到云端，迁移升级到 `0004_procurement_execution_test`，并完成受控认领和未绑定资源分单联调。部署详情见 [`20260825-采购执行测试版云端联调.md`](20260825-采购执行测试版云端联调.md)。
