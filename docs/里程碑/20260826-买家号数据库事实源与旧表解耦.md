# 买家号数据库事实源与旧表解耦

日期：2026-08-26

状态：共享测试部署、`0012` 凭证迁移、旧表完整数据迁移和独立 Base 持续同步均已完成。

## 结果

- 资源中心“买家号库”改为通过云端 API 查询 PostgreSQL，不再调用旧飞书表读取记录。
- 采购执行的买家号选择继续使用同一 `buyer_accounts` 事实表，列表、查重、占用和下单状态没有第二套数据源。
- 号商入库改为数据库批量预检和完整快照写入。账号、密码、Cookie、接码 Key/链接等凭证经认证加密后落库；已授权资源接口和同步 Worker 仅在内存中解密。
- 测试版环境创建和注册入口拒绝直写旧台账；旧表手工重试入口停用。旧代码只保留给明确的一次性迁移/回滚工具，不进入 Web 运行链路。
- 新增 `0011_buyer_db_base_mirror`：买家号增加安全来源字段及 Base 同步状态，`operational_sync_outbox` 支持 `buyer_account`。
- 新增 `0012_buyer_account_credentials`：买家号增加加密凭证封装与来源业务资料；完整数据查询需额外权限 `resource.buyer.credential.read`。
- 数据库快照、建环境成功合并和下单状态变化都会在同一事务生成买家号镜像事件。Worker 按新表“账号引用”幂等 upsert；旧版本事件晚到时标记 `superseded`，不能覆盖当前状态。
- 飞书连接页不再自动读取旧表；只有超级管理员显式点击“只读验证旧迁移源”才会查询旧表字段。

## 数据边界

PostgreSQL 保存：账号稳定引用、站点、源可用性、凭证状态、来源批次、Hub 环境引用、采购员、下单占用、Base 同步状态，以及加密的完整账号凭证与迁移业务资料。

禁止进入数据库/Base 的是系统级 Secret、数据库加密密钥、访问令牌和原始外部响应。完整邮箱/手机号、密码、Cookie、接码 Key/链接属于本次明确授权的买家号业务数据：数据库加密保存，测试 Base 明文协作镜像；仍禁止进入日志、Git、截图和测试夹具。

新 Base `Xynigo 买家号资源同步测试表 / 买家号安全同步测试表` 只接收 PostgreSQL 镜像，不承担业务查询、唯一性、锁、查重或状态裁决。

## 一次性迁移

模块 `purchase_tool.legacy_buyer_migration` 读取旧表 23 个既有字段，在内存中生成最多 500 条完整快照。默认 dry-run；真实迁移必须同时给出 `--apply --confirm-full-credential-migration`。发现无效站点或无法规范化的数据时整批中止，不猜测、不部分写入；输出仅含数量，不打印内容。
