# 20260824 云端认证服务骨架

## 里程碑结论

Xynigo 已新增独立的 `cloud/auth-service/`，作为运营采购助手、运营中心、财务中心及后续外部服务的统一身份基础。当前完成的是可测试、可迁移的代码骨架，不代表腾讯轻量服务器已经建库或服务已经开放。

用户、角色、权限、会话和审计统一使用云端 PostgreSQL。飞书多维表继续承担协同业务数据，不作为登录会话或权限裁决的事实源；本地采购电脑也不保存全局用户表。

## 本次完成

- 独立 Python 3.12/FastAPI 服务，不向现有 Python 3.9 本地采购包增加依赖。
- 飞书 OAuth v3 登录起始与回调，使用一次性 `state` 和 PKCE S256。
- 按 `tenant_key + open_id` 映射 Xynigo 用户，不以邮箱或手机号作为身份主键。
- 新成员默认待审批；超级管理员必须用环境变量中的明确 `open_id` 初始化。
- HttpOnly、Secure、SameSite=Lax 会话 Cookie；数据库只保存随机会话值的 SHA-256 摘要。
- 飞书用户令牌仅在回调内读取身份，用后丢弃，不进入业务表和日志。
- 首次 Alembic 迁移包含租户、用户、角色、权限、授权关系、会话、OAuth 尝试和审计九张表。
- `/healthz`、`/readyz`、登录、回调、`/v1/auth/me`、退出接口。
- Docker Compose 中 PostgreSQL 只连接内部网络，不发布 5432；认证端口只绑定服务器本机 `127.0.0.1:8080`。

## 安全决策

- 生产回调强制 HTTPS，并要求配置飞书租户白名单。
- 登录成功跳转只接受同源绝对路径，避免开放重定向。
- OAuth state 五分钟内有效、只使用一次，PKCE verifier 消费后清空。
- 不采用“首个登录用户自动成为超级管理员”的不确定规则。
- 前端返回角色和权限摘要，但后续业务接口仍必须各自执行后端鉴权。
- 仓库只保存 `.env.example` 占位模板，实际数据库密码和飞书 App Secret 不进入 Git。

## 验证结果

- 云端服务合成测试覆盖：超级管理员登录、权限初始化、会话摘要、当前用户、退出撤销、新用户待审批、OAuth state 防重放、健康和就绪检查、生产配置安全校验。
- 测试使用本地 SQLite 临时数据库与假的飞书客户端，不访问真实飞书、不写生产数据。
- PostgreSQL Alembic 迁移需在服务器容器环境再次执行升级与回滚演练。
