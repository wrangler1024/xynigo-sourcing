# 20260824 云端认证服务骨架

## 里程碑结论

Xynigo 已新增独立的 `cloud/auth-service/`，作为运营采购助手、运营中心、财务中心及后续外部服务的统一身份基础。代码骨架已经部署为腾讯轻量服务器上的隔离测试实例，但尚未接管正式采购业务。

用户、角色、权限、会话和审计统一使用云端 PostgreSQL。飞书多维表继续承担协同业务数据，不作为登录会话或权限裁决的事实源；本地采购电脑也不保存全局用户表。

## 本次完成

- 独立 Python 3.12/FastAPI 服务，不向现有 Python 3.9 本地采购包增加依赖。
- 飞书 OAuth v3 登录起始与回调，使用一次性 `state`；代码默认 PKCE S256，并支持受控兼容开关。
- 按 `tenant_key + open_id` 映射 Xynigo 用户，不以邮箱或手机号作为身份主键。
- 新成员默认待审批；超级管理员必须用环境变量中的明确 `open_id` 初始化。
- HttpOnly、Secure、SameSite=Lax 会话 Cookie；数据库只保存随机会话值的 SHA-256 摘要。
- 飞书用户令牌仅在回调内读取身份，用后丢弃，不进入业务表和日志。
- `0001_identity_foundation` 包含租户、用户、角色、权限、授权关系、会话、OAuth 尝试和审计九张业务表；`0002_local_login_bridge` 新增本地登录请求表和关联关系。
- `/healthz`、`/readyz`、登录、回调、`/v1/auth/me`、退出接口。
- 本地一次性登录桥：请求五分钟过期、轮询令牌摘要存储、数据库行锁和单次消费。
- Docker Compose 中 PostgreSQL 只连接内部网络，不发布 5432；认证端口只绑定服务器本机 `127.0.0.1:8080`。

## 测试部署结果

- 测试域名：`https://xynigo.samforo.icu`。
- HTTPS：Let's Encrypt 证书已签发，当前有效期至 2026-11-22，服务器已有自动续期任务。
- 数据库：已执行 `0001_identity_foundation` 和 `0002_local_login_bridge`；10 张业务表加 `alembic_version` 共 11 张 public 表。
- 网络：Nginx 只向 `127.0.0.1:8080` 反向代理；PostgreSQL 没有宿主机监听端口。
- 恢复：已生成 `root:root 0600` 的首次备份，恢复到临时数据库后核对表数与迁移版本，随后删除临时库。
- 持久化：分别重启 PostgreSQL 与认证容器后，服务恢复就绪，迁移版本和表结构保持不变。
- 外部服务隔离：本地采购服务、HubStudio 与现有 n8n 容器均未切换或重启。
- 真实 OAuth：云端服务已从 `samforo-cli` 切换到“小犀代采”，精确回调 URL、超级管理员登录、权限摘要、会话落库和本地登录桥均已验证。

## 安全决策

- 生产回调强制 HTTPS，并要求配置飞书租户白名单。
- 登录成功跳转只接受同源绝对路径，避免开放重定向。
- OAuth state 五分钟内有效、只使用一次，PKCE verifier 消费后清空。
- 不采用“首个登录用户自动成为超级管理员”的不确定规则。
- 前端返回角色和权限摘要，但后续业务接口仍必须各自执行后端鉴权。
- 仓库只保存 `.env.example` 占位模板，实际数据库密码和飞书 App Secret 不进入 Git。
