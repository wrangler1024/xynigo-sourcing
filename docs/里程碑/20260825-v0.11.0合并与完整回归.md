# v0.11.0 合并与完整回归

日期：2026-08-25

## 结论

GitHub 稳定版 v0.10.0 的本地执行器、安全并行、本地任务协调与 HubStudio 调用闸门，已经和当前飞书认证、RBAC、采购中心、认领、分单、采购执行测试队列及运营采购助手本机桥合并。统一协同测试候选版本为 v0.11.0，稳定渠道仍保持 v0.10.0。

本轮没有部署或重启共享测试服务器，也没有触发认领、分单保存、真实下单、店小秘审核、SHEIN 写入或飞书同步。原有 8767 和 8771 本地服务保持运行。

## 回归结果

- 本地应用单元与路由测试：248 项通过，3 项按环境跳过。
- 云端认证与采购服务：37 项通过；仅保留现有 Starlette TestClient 弃用提示。
- 运营采购助手：28 项 Node 测试通过，4 个 JavaScript 入口语法检查通过。
- 插件合成浏览器回归：采购明细注入、草稿保存、正式提交提示、编辑器保持、脱敏缓存和不触碰店小秘审核均通过。
- Alembic：唯一 head 为 `0004_procurement_execution_test`，从空库到 head 的 PostgreSQL 离线 SQL 可完整生成。
- 云端容器：`xynigo-auth-service:v0.11.0-regression` 构建成功，容器内版本为 v0.11.0，并以非 root 用户运行。
- 本地绿色包：macOS arm64 自检通过；Windows 包结构、版本和文件校验通过；两个包的渠道均为 `test`。
- 插件构建：开发目录和 `xynigo-dxm-purchase-assistant-v0.11.0.zip` 生成成功，Manifest 与 package 版本一致。

## 发布阻断项

公共源码安全审计当前未通过。原因是本次认证/部署交接提交中包含内部架构决策和项目记忆文档，其中记录了真实基础设施 IP；测试代码中的文档保留地址和本机已忽略的历史查询日志还会产生附加提示。

因此当前提交可以继续用于本地和共享测试环境灰度，但不得推送为公开稳定发布。发布前必须将内部部署文档迁移到私有运维仓库或完成脱敏，并在干净工作树重新通过 `scripts/audit_public_release.py`。

## 已知测试边界

- 飞书 Base 同步 Worker 尚未部署，`syncStatus=pending` 不能解释为已写入 Base。
- 采购执行中的 Hub 环境与买家号绑定、真实下单、平台订单回填仍是禁用占位。
- 本轮只读访问共享测试数据，没有再次制造采购单、认领或分单数据。
- 生产环境没有进入本轮操作范围。
