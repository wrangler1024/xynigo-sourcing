## 功能边界

- 普通采购协作表中已经导入的历史订单不能通过重新导入修改。
- 跨批次完全一致的历史订单整单跳过；目标表中已有多个完整相同副本时仍视为“已存在”，不自动清理历史重复。
- 历史明细与本次明细不一致时，在新增任何行之前阻断；“采购任务认领前可修订”继续由 PostgreSQL 采购任务和店小秘插件承担。
- XYP2 同一 SKU/规格的多条销售来源行会聚合数量和商品金额，数量一致时不再生成误导性的黄色关注。
- 页面执行状态覆盖校验、表头规范、追加、回读、底色、链接和图片阶段，完成态给出新追加、已存在、底色、链接和图片计数。

## GitHub Actions 事故处理

2026-08-26 GitHub Actions 发生官方重大事故。最初公开分支 run `32984758350` 在平台未创建任何 job 的情况下被取消；原地重跑后又长期保持 `queued / jobs=[]`。2026-08-27 官方状态恢复为 All Systems Operational，但该事故期记录的查询、取消与重跑端点仍互相矛盾。

为避免改动已验收代码，发布使用指向同一公开提交的临时验证分支触发全新 run `33032393401`；六任务全绿后立即删除临时分支。随后才创建正式注释标签，并等待标签 run `33032507750` 六任务全绿后创建 Release。没有把事故期平台取消误判为代码失败，也没有跳过标签 CI。
