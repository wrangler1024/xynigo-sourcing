# 采购助手子订单查询

采购协作表中的「系统订单键」属于导入时的原始母单，采购在销售订单号后添加子单后缀时仍应保留。采购助手将「母单键、店铺、完整销售订单号、包裹号」规范化后，以 JSON 数组编码生成 `PT1-` 前缀的 SHA-256 采购任务标识。不会修改表格，也不会按数字后缀猜测或截断订单号。

同一母单下的 `SYNTH-ORDER-1`、`SYNTH-ORDER-2`、`SYNTH-ORDER-3` 是不同的采购任务；同一子单的多条明细仍聚合展示。任务标识不依赖表格行号、行顺序或其他子单是否存在。导入去重仍使用原始母单身份，采购任务标识不写回系统订单键列。

搜索结果中的 `taskKey` 是用于选单和读取收件信息的标识；`sourceOrderKey` 保留原母单身份，用于兼容按原键搜索。销售订单号、包裹号及店铺搜索保持现有匹配规则。任务摘要不包含姓名、电话、地址或 CURP。

收件信息接口只取当前采购任务的明细，不从其他子单借用地址或 CURP。同一子单没有完整地址时拒绝填写，存在多组不同的完整地址时继续阻断；CURP 的缺列、空值和冲突规则不变。

旧客户端缓存的原始任务键仅在能唯一对应一个当前采购任务时兼容读取；同一母单已对应多个子单时返回业务错误，要求重新搜索选择。不能将旧母单卡片默认为第一条子单。子单号改动后，旧采购任务标识失效，需要重新查询。

本功能位于采购电脑运行的 Xynigo 本地执行器。现有插件会透传任务键，其长度限制兼容新的 68 字符标识；无需修改浏览器插件前端。仅部署云端网页不能更新采购电脑中的查询逻辑。插件源码仓库中的脱敏开发 provider 也同步使用相同规则，不改动既有发布包。

回归：`tests/test_purchase_assistant_suborders.py` 与 `tests/test_purchase_assistant.py` 覆盖多子单搜索、HTTP 选单和收件信息读取、旧键保护、行顺序、店铺/包裹隔离、地址与 CURP 范围，并联动验证导入去重仍跳过已有母单明细。
