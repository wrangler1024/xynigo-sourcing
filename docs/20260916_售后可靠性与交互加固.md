# 售后可靠性与交互加固

基线：main `e723f7f`。分支：`codex/after-sale-reliability-ux`。
范围：按模块评估修复可靠回传、多包裹记录、任务控制和前端交互；未推送、未部署、未提交真实退款。

## 实现

- 每个包裹生成退款号后立即保留凭证；后续资格/账户读取或第二包失败仍保留已受理记录。部分失败保持失败订单口径，并在页面标明已有受理包裹，历史与导出显示全部退款号，回访展开全部包裹。
- finish 携带完整结果行，与云端终态同事务入库；上传失败的进度不记为已确认。结果行不完整时标记 uncertain，不能把缺失行解释为完成。
- 新任务通过可靠结果能力门槛；迁移 0040、闭集字段和升级顺序见《生态跨仓契约》。
- 提交资格复用严格只读校验；无法识别的回访页面返回失败，明确已受理节点仍支持全文兜底，失败读取不覆盖之前的有效平台阶段。
- 回访增加独立取消路由；运行中禁止清空结果；三入口在首个 await 前锁定发起状态，失败重试同一报文复用幂等键。
- 终态标题区分取消、失败、待核对及部分失败。扫描发起时重置进度。移除没有实际保障的“终态冻结”承诺，明确可重复只读回访。
- 手工输入改为多行文本，支持中英文分号和换行；回访错误组、重复组明确提示，存在错误时不发送部分清单。
- 窄屏运行条换行，停止按钮保持可见；输入区沿用统一网格。补齐本机提交路由对商品图、送达时间的透传。

## 验证

- 本地全量阶段性回归 1165 passed / 5 skipped；后续新增全文兜底与不完整回执测试，受影响专项 206 项通过。
- 云端新增端到端测试覆盖无进度上传的最终结果入库、结束回执重复发送、无效结果事务回滚、多包裹历史/导出、失败回访保留旧阶段、回访取消路径及旧能力拒绝。
- SQLite 与独立临时 PostgreSQL 16 均验证 0040 升级、新旧记录默认值及回退保留原字段数据。临时 PostgreSQL 容器已销毁，无共享数据库操作。
- Playwright 合成页面在 1440/768/375px 验证运行条无横向溢出、停止按钮可见、多行输入对齐和格式错误阻断。截图位于忽略目录 output/playwright/。
- 源/云端 Web 与两份原型同步，JavaScript 语法、公开安全审计和 diff 检查通过。

## 限制

本次只验证合成业务流程，没有真实平台退款验收。平台受理与本地进程并非一个事务；进程崩溃或尚未取得退款号时仍需人工核对。旧记录过去已经丢失的多包裹退款号不能凭空恢复。新增数据库列尚未部署。
