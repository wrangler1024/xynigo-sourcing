# 阶段 2 云端运行链路交付说明

## 目标

把“页面等待本机 RPC 返回”的临时链路改为“云端 Run 是任务事实源、本地执行器只负责执行”的正式链路。页面刷新、重新登录或短时网络中断后，进度从 PostgreSQL 恢复，不重新向执行器读取整批历史结果。

## 已实现

- 新增环境创建、物流查询两类持久化 Run，支持幂等提交、执行器绑定、阶段、尝试次数、逐行进度、出口 IP 状态、安全停止和终态查询。
- 新增正式执行器任务：`environment.create-bound.v1`、`environment.create-backup.v1`、`logistics.query.v1`。
- v0.13.2 将买家号 xlsx 的格式解析、字段校验、文件内去重和 Cookie 站点校验迁至云端。原始文件只在请求内存中解析，不写普通数据库；结构化执行计划使用 AES-GCM、租户与计划 AAD 加密保存 30 分钟，页面只得到脱敏预览。
- 云端按“租户 + 用户 + SHA-256(文件内容、站点、采购分组)”复用仍为 `parsed` 且未过期的计划。数据库部分唯一索引保证并发上传最终只保留一条有效计划；独立请求映射表保留每个 `idempotencyKey` 的精确重放结果，重复上传不重复解析也不消耗活跃计划额度。
- 对外统一使用 `cloudPlanId`。正式 Run 和加密执行器任务携带 `cloudPlanId`；执行器导入后生成只存在本机短期内存的 `planId`，两者不再共用名称。Run 请求临时兼容旧字段 `planRef`，但进入服务后立即规范化为 `cloudPlanId`。
- 用户点击“正式执行”后才选择支持 `environment.cloud-plan.v1` 的执行器。云端再次绑定站点、采购分组、账号数量和计划所有者，并把结构化计划放入原有加密任务信封；本地执行器严格反序列化后才进入 HubStudio 预检与写入。
- 正式任务创建成功后立即清除计划表密文；任务完成、取消、执行器撤销或启动后租约失效进入不确定状态时，再清除任务信封中的请求密文，仅保留不可逆载荷哈希用于幂等判断。
- 环境创建的站点、采购分组和采购员分配改为任务参数；站点/分组最后选择保存到云端用户偏好，不再为每次切换创建执行器 RPC 任务。
- 执行器每次状态变化上传脱敏行快照；租约续期同时刷新 Run 心跳。云端拒绝未脱敏邮箱、额外凭证字段和不合法终态摘要。
- 云端 Web 的正式建环境、备用/测试环境、首次物流查询、单行重查和异常批量重查均提交 Run；页面轮询 Run API，并在刷新后读取当前用户最近一次 Run。
- 页面安全停止改为取消云端 Run 对应任务。执行器在续租响应中发现取消请求后，调用本机协作式停止，不强切正在写入的一整行。
- 新增 `workspace.snapshot.v1` 聚合任务。云端保存经过严格字段校验的最近一次站点、分组、环境偏好和双站 preflight 快照；页面先恢复旧快照，再后台刷新并显示更新时间，不再为初始化分别创建通用 RPC 任务。
- 环境单行重试和批量失败重试新增独立 Retry Run。子 Run 关联父 Run，只执行当前有效失败行；页面刷新后沿父链合并原批次结果，已在前一次重试成功的行不会再次进入失败批量。
- 本机任务完成后仍通过结果接口补齐完整业务结果和 Feishu outbox；Run 进度与最终结果使用同一 `runKey`，不会生成两份批次。

## 现场问题覆盖

- 页面切回、刷新或重新登录后批量进度重新获取且卡顿：改为直接读云端 Run 和逐行结果。
- “正在提交”持续很久、执行器响应中断后不确定是否受理：创建 Run 后立即返回 `202` 和稳定任务编号，重复提交由幂等键去重。
- 任务状态反复跳动、执行完成后按钮仍长时间停留在执行中：统一使用 Run 状态和终态，不再拼接多条本机 RPC 状态。
- 查询物流开始按钮要点多次、重新查询无反应：首次查询和两类重查均成为正式任务，可查询、可取消、可恢复。
- 环境创建并发、出口 IP 检测和逐步状态不可见：云端持久化实际逐行步骤、成功/失败/停止计数和 IP 检测进度。
- 错误站点或采购分组导致解析/执行失败：正式任务显式携带并校验站点和采购分组；页面流程保持先选择站点/分组，再上传解析。
- 上传解析受“执行器忙、离线或旧偏好任务排队”影响：云端解析不再依赖执行器在线，错站和格式错误直接返回稳定错误码与安全的行号说明。
- 解析成功后刷新页面要重新上传：同一登录用户、站点和分组会恢复尚未过期的云端加密计划；提交正式 Run 后立即销毁计划表中的加密正文。
- 重复上传占满五个计划额度、旧请求覆盖新选择：服务端内容去重后返回 `reused: true` 和原 `cloudPlanId`；页面显示计划有效时间，并用上传 revision 与站点/分组快照丢弃过时响应。

## 通道边界

当前仍使用出站 HTTPS 长轮询领取命令和续租。长轮询只承担命令通知与租约，不再承担页面批量进度查询；PostgreSQL Run 是任务事实源。后续如改 WSS，只替换通知层，Run、幂等、租约、停止和结果模型无需重做。

## 2026-09-02 共享测试反馈改造（待发布）

- 新环境 Run 提交时立即清空上一批表格、摘要和 IP 结果；轮询期间若新 Run 尚无逐行数据，显示本批“正在预检和准备”，不再残留其他站点历史结果。
- 出口 IP 检测保留稳定错误码与安全错误摘要，区分 HubStudio 未返回 IP、归属地查询失败、国家代码缺失、国家不匹配、浏览器内核缺失及其他 Local API 错误，不再统一显示“未知”。
- 重复执行同一文件时，页面分别统计“本批新建”和“历史恢复”；同组已完成环境明确显示“已存在，未重复创建”，避免采购误认为再次写入。
- 环境任务的停止语义升级为“停止并撤销”：停止领取新行，等待已进入执行的整行收尾，再调用 HubStudio `/api/v1/env/del` 销毁当前 Run 确认新建的环境。`recoveredExisting=true` 的历史环境永不进入自动删除目标。
- 每行持久化 `createdInRun`、清理状态、清理错误和 IP 检测错误；删除超时后按精确 containerCode 回查，已不存在视为幂等成功，ID 与环境名不一致则失败关闭，禁止误删。
- 撤销成功后清除本批本机断点，同一原始文件可以修改日期、站点、分组或采购员分配后生成新 `cloudPlanId` / Run 再次执行；销毁失败行保留稳定原因，重新执行前仍需先完成清理。
- 云端会把同租户历史 `cleanupStatus=failed` 的脱敏账号引用随新任务下发；本机实时预检若仍看到对应旧环境则在任何写入前整批阻断，人工删除旧环境后再次预检会自然放行，禁止把不符合预期的旧环境静默当作正常恢复结果。
