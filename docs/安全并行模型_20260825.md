# Xynigo 安全并行模型

日期：2026-08-25
对应版本：v0.10.0

## 目标

在不改变真实写入确认和同环境禁双开的前提下，允许订单物流查询与一种环境创建任务在同一本地执行器内并行运行。

## 准入矩阵

| 任务组合 | 安全并行开启 | 兼容串行 |
|---|---:|---:|
| 物流查询 + 买家号建环境 | 允许 | 阻止 |
| 物流查询 + 备用/测试环境 | 允许 | 阻止 |
| 物流查询 + 注册 | 阻止 | 阻止 |
| 买家号建环境 + 备用/测试环境 | 阻止 | 阻止 |
| 两个物流查询批次 | 阻止 | 阻止 |
| 两个环境创建批次 | 阻止 | 阻止 |

## 本地执行规则

1. `LocalTaskCoordinator` 在任务启动前原子登记任务类型与资源。
2. 查询任务预占目标环境的规范化环境名和 `containerCode`。
3. 环境创建任务在预检计划生成后、任何 HubStudio 写入前预占计划环境名；断点恢复的既有环境同时预占 `containerCode`。
4. worker 再次读取 HubStudio 后补充预占，防止预检与实际执行之间的计划漂移。
5. 任务无论成功、失败或停止都通过完成回调释放资源。
6. `HubRuntimeGate` 将 Local API 同时请求限制为 4，并串行提交浏览器 start/stop 控制 RPC。
7. 安全并行开启时，买家号及备用环境创建线程数自动封顶为 3。

## 不变量

- 真实 HubStudio 写入继续要求显式确认。
- 飞书回写继续要求单独确认、写前冲突预检和写后回读。
- 同一环境不能被两个本地任务同时打开或修改。
- 密码、Cookie、接码 Key、代理链接和飞书标识不进入任务协调器、任务状态接口或日志。
- 本地资源预占不宣称具备跨电脑原子互斥能力。

## 回退

系统设置关闭“安全并行”后恢复 v0.9.0 的跨模块串行准入；该设置不会改变批次数据、断点文件或飞书台账结构。运行中禁止切换，必须等待所有后台任务结束。
