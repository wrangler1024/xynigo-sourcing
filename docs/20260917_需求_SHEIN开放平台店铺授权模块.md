## 1. 背景与目标

SHEIN 开放平台卖家自研资质已认证（主体：深圳市歆悦购数字科技有限公司），应用「Xynigo ERP（自运营）」已过审（APP_ID `1636F90749001A002A60B0C187361`），第一家店铺（观潮，商家ID 18301880）已通过手动流程完成授权并验证全部接口（额度/品牌/订单/财务）。本模块把手动的授权流程**产品化**为云端工作台的店铺授权管理，支撑后续财务、订单、商品数据模块的店铺级供数。

**不在本期范围**：财务/订单数据的采集与展示（另立规划）；半托管第二应用的实际创建（仅预留设计）。

## 2. 依赖的已验证契约（全部真机实测，20260916-17）

| # | 契约 | 要点 |
|---|---|---|
| 1 | 授权链接 | `https://openapi-sem.sheincorp.com/#/empower?appid={appid}&redirectUrl={redirectUrl整体base64}&state={自定义}`；授权页域名 ≠ 接口域名 |
| 2 | 回调 | 店铺**主账号**在登录卖家中心的浏览器打开链接并同意 → 跳转 redirectUrl，URL 尾附 `tempToken`（**10 分钟有效、一次性**）与 `state` |
| 3 | 换取密钥 | `POST /open-api/auth/get-by-token` body `{tempToken}`；签名用**应用**凭证，请求头 `x-lt-appid/x-lt-timestamp/x-lt-signature`；返回 `openKeyId` + **AES-128-CBC 加密的 secretKey** |
| 4 | 解密 | key=APP_Secret 前 16 字节，IV=固定种子（实测 `space-station-de` 生效），解密后为 32 位十六进制串 |
| 5 | 业务调用 | 店铺 `openKeyId` + 解密后 `secretKey` 签名，头 `x-lt-openKeyId`；自运营接口域名 `https://openapi.sheincorp.com`；`x-lt-language: CN` 可选 |
| 6 | 签名算法 | `VALUE=openKeyId&timestamp&path`，`KEY=secretKey+RandomKey(短串)`，HMAC-SHA256→hex→base64，`signature=RandomKey+base64(hex)` |
| 7 | IP 白名单 | 生产调用出口必须加入控制台白名单（单 IP 或 /24-/31，总数<300）；**换出口 IP 即 401** |
| 8 | 密钥轮换 | 每次重新授权生成新 secretKey，**以最新授权记录为准**；控制台「授权记录」可查（邮箱验证后 1 小时内可见明文，兜底找回） |
| 9 | 店铺信息 | `POST /open-api/openapi-business-backend/query-store-info`（已订阅）用于验证凭证与展示店铺资料 |
| 10 | 限流 | 订单类 100 次/秒；授权换钥接口无感知限制（低频操作） |

## 3. 模块设计

### 3.1 页面（云端工作台 `src/purchase_tool/web/`，权威源，经 `sync_web_workspace.py` 同步）

新增「店铺授权」页面，三区布局（UI 细节先出静态原型经 Jeff 确认后再开发，遵循既有偏好）：

1. **授权引导区**
   - 「生成授权链接」按钮 → 后端产生一次性 `state` → 展示完整链接 + 一键复制；
   - 内嵌操作说明（发给店铺主账号所在浏览器打开 → 同意授权 → 自动跳回）；
   - 链接有效期提示（本质取决于 tempToken 10 分钟窗，从用户同意那刻计时）。
2. **已授权店铺列表**
   - 列：店铺名 / 商家ID / openKeyId（掩码）/ 模式（自运营）/ 首次授权时间 / **最新授权时间**（密钥轮换标记）/ 最近验证时间 / 状态（正常·凭证失效·未验证）；
   - 行操作：验证连接（调店铺信息接口）、重新授权（本质=再走一次链接，成功后更新密钥与最新授权时间）、停用/删除。
3. **授权事件流**（P1，可后置）：tempToken 回调事件与结果的流水记录。

回调路由：工作台新增 `/shein-auth/callback`（接收 URL 尾部 tempToken+state → 调后端换钥 → 展示成功/失败页）。**redirectUrl 必须为 https 站点页面**，本工作台域名满足。

### 3.2 后端（`cloud/auth-service/src/xynigo_auth/`）

沿用 contract+service+crypto 三件套模式：

- `shein_store_auth_contract.py`：请求/响应契约（Pydantic），字段掩码规则；
- `shein_store_auth_service.py`：业务逻辑；
- `shein_store_auth_crypto.py`：店铺 secretKey 的服务端静态加密（密钥来源与环境变量体系同现有 `*_crypto.py` 先例）；
- `shein_openapi_client.py`（新，供后续财务/订单模块复用）：签名、get-by-token、通用 POST、店铺信息/额度等只读接口封装；**应用凭证从部署配置读取，不落库不落日志**。

接口（挂 `main.py`，走现有鉴权与租户体系）：

| 接口 | 说明 |
|---|---|
| `POST /api/shein-auth/link` | 生成一次性 state 并返回授权链接 |
| `POST /api/shein-auth/callback` | `{tempToken, state}` → 校验 state → 换钥 → 解密 → 拉店铺信息 → upsert 凭证（加密） |
| `GET /api/shein-auth/stores` | 已授权店铺列表（全部掩码，不回传 secretKey） |
| `POST /api/shein-auth/stores/{openKeyId}/verify` | 调店铺信息接口验证凭证活性，更新状态与最近验证时间 |
| `POST /api/shein-auth/stores/{openKeyId}/disable` | 停用（软删，保留历史） |

### 3.3 数据模型（Alembic 迁移）

```
shein_authorized_store
  id, tenant_id
  merchant_id          -- 商家ID（如 18301880）
  store_name           -- 店铺名（query-store-info / 手工补充）
  open_key_id          -- 平台 openKeyId，租户内唯一
  secret_encrypted     -- shein_store_auth_crypto 加密
  app_id               -- 所属应用（预留多应用/多模式）
  mode                 -- 自运营 | 半托管（预留）
  first_authorized_at, latest_authorized_at
  last_verified_at, status, store_info_json
shein_auth_event
  id, tenant_id, state, temp_token_masked, result, reason, created_at
```

注意事项（从实测坑沉淀）：
- `latest_authorized_at` 是密钥版本的事实标准（平台明示以最新授权记录为准），列表必须展示；
- 迁移须给 `created_at`/时间列 server_default（售后模块 0038 迁移教训）；
- 结构断言测试钉列序（售后模块方法论）。

### 3.4 安全要求（红线）

1. secretKey 仅以加密形态落库；接口层、日志、business_log 全掩码；前端永不回传；
2. tempToken 只在后端内存中使用，事件表只存掩码；
3. state 一次性、绑定租户与操作人，回调校验后即失效；
4. 应用 APP_Secret 只存部署配置（对齐仓内「凭证不入公开文件」规则）；
5. 生产出口 IP 必须为服务器固定出口（腾讯云），**不得依赖办公网/代理出口**（当前平台白名单里的 Clash 出口仅是手动验证期临时项，部署验收时替换为服务器 IP 并清理临时项）。
