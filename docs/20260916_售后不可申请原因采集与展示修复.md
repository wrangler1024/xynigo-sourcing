# 售后不可申请原因采集与展示修复

## 现场结论

用户授权只读核对截图订单，并补齐采集与前端显示。六个目标环境均已完成只读核查：平台卡片的具体状态为 `En revisión vendedor/SHEIN.`，即卖家/SHEIN审核中；同时订单主状态为 `Procesamiento de reembolsos`，即笼统退款流程状态，且没有丢件退款入口。一个环境首次未取得目标卡片，按正式分页读取函数重试后核对成功，没有把首次读取失败当成业务状态。

真实环境、订单映射保留于私有测试记录，不进入公开仓。没有提交退款，没有修改平台订单；只关闭了本次打开的环境，用户原有环境保留。

## 原因

- 卡片采集仅提取主状态，未单独采集 `.status-ctn_text` 中的审核节点。
- `refundInProgress` 布尔值及 `scan_unavailable_note` 将审核中和退款处理流程合并为一句泛化描述。
- 执行器到云端的扫描闭集没有平台状态原文及读取时间；Web 对原因只显示前 60 字。

## 修复

- 采集卡片内具体状态，优先区分卖家/SHEIN审核中、退款处理中、已退款、退款已处理；笼统流程状态明确标注详细阶段待核对。银行处理中不再当作已到账。
- 仅根据卡片状态提供原因；未发现入口但证据不足时标注原因待核对，不能猜成超期或重复提交。可申请性仍由既有只读资格接口核验，新增说明不放宽提交条件。
- 扫描行新增可选字段：`reasonCode`（64）、`platformStatus`（240）、`reasonSource`（32）、`checkedAt`（40），括号为字符上限；贯穿执行器订单行投影和云端闭集校验。旧行缺省为空，无数据库迁移。
- 清单完整显示原因，支持展开查看平台原文、资格判断来源、带时区的读取时间；历史泛化结果提示重新扫描，不凭历史记录猜测当前阶段。
- Excel 保留完整原因，并在既有列尾追加平台订单状态原文、资格判断来源、最近读取时间。原文仍按文本单元格保存，不执行为公式。

## 验证与发布边界

- 本地采集、投影、Web 与相关回归 167 项通过；包含具体节点优先、笼统状态保留不确定性、银行处理中不当成已到账、长原因不截断和 HTML 转义。
- 云端专项覆盖新字段通过进度快照和导出、旧行默认值、Excel 原文与读取时间，12 项通过。
- 需要先部署兼容新可选字段的云端及 Web，再发布执行器安装包；旧云端的闭集会拒绝新增字段，不得先发执行器。旧执行器可继续上报旧格式，但获得具体原因须升级执行器后重新扫描。
- 本轮是代码修复，尚未部署或发布新安装包；现场已确认真实业务状态不等于用户当前安装版已包含该修复。独立评审已通过，无剩余必须改项，发布另行安排。
