# Xynigo 生态跨仓契约

状态：v1 定稿 · 20260910，经 Jeff 确认。本文维护共同接口的归属、兼容要求与验证入口，不宣称尚未完成的集成已经上线。较新功能和测试按 [源码核对基线](../CONTRIBUTING.md#源码核对基线) 解释；下文主仓源码/测试路径相对此基线，代码链接固定到该公开提交。版本、实现与部署状态分别核验。

插件仓为 [crossborder-userscripts](https://github.com/wrangler1024/crossborder-userscripts)。以下“插件路径”均相对该仓根目录，主仓路径相对本仓根目录。普通克隆和 worktree 均按仓库身份定位邻库，不依赖固定父目录。

## 契约地图

| 契约 | 生产者 → 消费者 | 当前边界 |
|---|---|---|
| XYP2 备注 | 提单助手 → 主仓导入与 XYP2 解析器 | 已实现 |
| 云端采购与身份 | 提单助手 ↔ 云端认证/采购服务 | 已实现：登录、续期、草稿、提交、读取及修改冲突 |
| 本机采购助手 API | 采购助手 ↔ 本地执行器 | 已实现：配对、任务/地址读取、能力协商和环境增强 |
| 精准采购链接 | 型号助手、主仓导入、提单助手 XYP2 重建 → 提单助手、售价对比 | 已实现：URL 查询与 fragment 元数据；选品器普通商品链接不在此契约内 |
| 物流标识与接入 | 采购/物流数据 → 物流助手 | 当前手工/文件输入；尚未直接接入云端物流查询结果 |

## XYP2

插件源：`extensions/xynigo-dxm-purchase-assistant/src/core.js`。主仓解析源：[procurement_import.py](https://github.com/wrangler1024/xynigo-sourcing/blob/e10e8a271b3316194a1f6a29a49e65f9f9adcf3a/src/purchase_tool/procurement_import.py)，云端副本由同步脚本生成；[XYP2 解析器说明](https://github.com/wrangler1024/xynigo-sourcing/blob/e10e8a271b3316194a1f6a29a49e65f9f9adcf3a/docs/xyp2-parser.md)复用同一解析规则。

变更须核对 `[XYP2]` 包围格式、明细顺序、字段类型、数量/价格单位、站点/币种/mallCode、必填与可选字段以及备注长度约束。不得以改变字段含义的方式复用旧格式；对旧备注缺失可选字段的行为须明确。

至少用合成样例验证：现有备注、新备注、截断/损坏备注、重复输入、多采购明细和多账号修订。有效历史备注不能仅因客户端升级失去可读性；需要停止支持时另行设计迁移或明确拒绝说明。不能把解码成功当作可重复写入的证明，导入幂等与修订语义也需回归。

验证入口：插件 `extensions/xynigo-dxm-purchase-assistant/tests/core.test.js`、主仓 `tests/test_xyp2_parser.py`、`cloud/auth-service/tests/test_procurement_import_cloud.py` 与 `cloud/auth-service/tests/test_xyp2_parser.py`；按变更扩大覆盖。

## 云端采购与身份

插件调用源：`extensions/xynigo-dxm-purchase-assistant/src/background.js`。草稿、提交、读取分别调用 `/v1/purchase-orders/draft`、`/submit`、`/get`（后两者沿用相同前缀）。还依赖登录、会话续期、退出及权限判断，不能只检查备注输出。

权威校验见 [purchase_contract.py](https://github.com/wrangler1024/xynigo-sourcing/blob/e10e8a271b3316194a1f6a29a49e65f9f9adcf3a/cloud/auth-service/src/xynigo_auth/purchase_contract.py)。变更须检查 `schemaVersion`、`orderKey`/系统订单键、来源销售行、金额归属、`expectedDraftRevision` 及冲突响应。请求只用于并发控制的字段不能悄然进入稳定哈希，跨账号修订不能覆盖他人较新的数据。

身份与权限是服务端边界；不能以隐藏前端入口替代鉴权，也不能让插件持有服务端密钥。增加字段前检查服务端严格校验，不能假设旧服务会忽略未知字段。

验证入口：插件 `tests/background.test.js`、`tests/source-associations.test.js`（均在提单助手扩展目录）；主仓 `cloud/auth-service/tests/test_purchase_api.py`、`test_purchase_source_associations.py`、`test_purchase_shared_revision.py`。

## 本机采购助手 API

插件源：`extensions/xynigo-shein-purchase-assistant/src/background.js`；协议前缀为 `/api/purchase-assistant/v1`，包含短时会话配对和能力探测。主仓验证入口：[test_purchase_assistant.py](https://github.com/wrangler1024/xynigo-sourcing/blob/e10e8a271b3316194a1f6a29a49e65f9f9adcf3a/tests/test_purchase_assistant.py)、[test_purchase_assistant_suborders.py](https://github.com/wrangler1024/xynigo-sourcing/blob/e10e8a271b3316194a1f6a29a49e65f9f9adcf3a/tests/test_purchase_assistant_suborders.py)。

声明最低能力和不支持时的行为，不要求插件与执行器版本号相等。能力声明、真实端点和错误码必须一致；环境增强不可用时能否保留核心地址读取，以已验证降级策略为准。

收件信息只在明确选中的任务范围返回；任务身份、地址冲突、字段映射、数据源选择与站点变更需要回归。回环来源、扩展配对、响应不缓存和敏感数据不持久化等边界不可因兼容旧版本而放宽。云端部署不能更新员工电脑中的本机执行器代码。

业务工作空间可能存在比正式插件仓更新的测试源码。发现这种差异时先记录来源、版本、功能与测试证据，经确认后归并到正式仓；不能用版本号较低的副本直接覆盖，也不能凭版本号较高就宣布其已正式验收。

## 精准采购链接

当前元数据生产者为型号助手 `scripts/shein-product-variant-helper/shein_product_variant_helper.user.js` 的 `buildPurchaseLink`、主仓 `procurement_import.py` 的 `_purchase_link`，以及提单助手 `extensions/xynigo-dxm-purchase-assistant/src/core.js` 的 `parseXyp2Remark`（从备注重建链接）。当前解析消费者为同一提单助手核心的 `parsePreciseLink` 和 `extensions/xynigo-shein-price-compare/core.js`；对应生成油猴脚本和打包副本不另算独立实现。

选品器 `scripts/shein-globalship-selector/shein_globalship_selector.user.js` 的 `formatProductLinks` 使用 `canonicalizeProductUrl` 清除 query 与 fragment，仅复制普通商品页面链接，不携带 `xv`，不属于本元数据契约的生产者或消费者。未来若增加精准采购链接功能，须先纳入本契约并补兼容验证。协作表及链接单元格负责完整保留 URL，不据此成为元数据的语义解析者。

当前链接含商品、SKU、mallCode 查询字段，以及 fragment 中的 `xv`、`p`、`s`、`op`、`cr`、`gp`、`c`、可选 `pt`。具体缺失值和接受条件以各消费者测试为准；不把审单原价、指导价和实际付款混成一个金额。

变更需验证生成、读取、导入重建后的往返结果，尤其是币种、规格、优惠比例、URL 编码和旧链接没有采价时间的情况。不要因调整一个插件而破坏另一插件的读取；售价对比构建还嵌入型号助手源码，需同时检查其包内容。

## 物流标识与未来接入

现有物流助手以手工粘贴或 Excel/CSV 接收订单号、采购子单号、物流单号和物流商渠道。它不直接读取云端采购或物流查询 API，也没有已经建成的云端幂等审计链路。

订单号、包裹 ID、采购子单号和系统订单键不是可互换字段。不得按子单序号、列表顺序或接口返回顺序猜测商品/包裹关系；平台受理不等于最终发货成功，超时或响应未知不等于失败可重试。

未来接入前需单独确认：字段和身份映射、来源与时效、权限范围、重复提交与结果未知策略、人工确认边界和云端审计。该设计与实现通过评审后再把本文状态改为“已接入”。

## 契约变更与发布顺序

每次变更记录：受影响契约、生产者/消费者、各仓候选 SHA、旧/新输入兼容结果、最低能力、发布顺序与回退条件。修改权威正文和受影响仓入口摘要，不在两仓复制整份规范。

默认先部署能兼容新旧输入的接收方，再发布产生新输入的一方；验证历史数据和旧客户端后，才考虑移除兼容。不能固定为“主仓永远先发”。插件自动更新、云端发布和桌面安装有不同生效时间，需考虑新旧版本共存。

跨仓 CI 不依赖作者机器的邻库目录。后续共同合成样例采用明确版本/提交固定引用，并在两仓验证；禁止从邻库默认分支实时获取数据而不固定来源。共享夹具与兼容矩阵的机器门禁仍待实施。

## 采购详情凭证（0.9.0 首版候选，未部署）

生产者：采购助手 `src/purchase-details.js` → 本机 `/api/purchase-assistant/v1/purchase-details` → 云端 `/v1/assistant/purchase-receipts`。本机健康接口增加 `features.purchaseDetailsV1`，不改变旧地址读取协议。云端凭证要求迁移 `0035_purchase_receipts`；只增加协议，不将旧只读代理改成任意写入代理。

本机 action：`read`、`submit`、`status`、`retry-image`。read 输入任务键、当前标签页 URL、随机 document 标记、用户确认的环境序号。通过云端查验数据源与任务，再连接已打开环境的唯一匹配标签页。返回短时 captureId、只读订单信息、JPEG 预览、目标信息与版本。submit 仅接受 captureId、confirmed 和修订原因，不接受客户端替换金额/图片。captureId 按登录成员隔离，30 分钟失效。

云端 action：`preview`、`submit`、`status`、`retry-image`。来源由云端登记的团队表 sourceId 解析。以 assistant.access 权限、租户、采购员列身份限制写入；个人速填表拒绝。身份键沿用 PT1 的 `[系统订单键或fallback,店铺,完整销售订单号,包裹号]`，保留人工拆单后缀，不按行号或截断订单号定位。

一任务一采购订单。多商品行只记一次金额和截图，订单号同步到同任务商品行；不更新采购状态。原币 MXN 保存在凭证记录；现有“实际付款”单元格保持数值，不混入币种文本，不新增表头。首版拒绝其他币种。

提交使用 requestId 幂等键、expectedRevision、任务 fingerprint。数据库持久化 slot 认领与每次不可变凭证，记录操作者、原因、时间、订单号、金额、币种、付款时间和原图。原图为业务凭证保存在租户数据库，不进入公开仓、日志或扩展持久存储。同采购订单不能分配给其他任务。修订需原操作者或管理员、有原因、明确版本，旧凭证通过 previous_id 留存。

状态为 pending → text_done → complete；明确图片权限/参数拒绝为 image_failed，可补图；任何无法确认的外部结果为 uncertain，不自动重试。进程在写入中终止保留 pending/text_done，后续仅查询，不盲目回放。截图验证绕过网关 image cache，读原单元格并比对原/后图指纹。人工已有值或图不被静默覆盖。

飞书不提供本方案已验证的事务式行身份 CAS。读回可检测并发变更，但不能消除人工排序与写入间的竞态；受控验收期间避免修改目标任务结构。未知结果仍需管理员核对，尚未实现自动恢复门禁。上线前必须验证权限名称与真实采购员列一致、图像写入读回形态，以及新旧客户端共存。

发布顺序：云端迁移和兼容接口 → 本机执行器 → 插件候选。现有云端部署不会更新本机执行器。独立评审、真实写入验收和分发授权分别记录。
