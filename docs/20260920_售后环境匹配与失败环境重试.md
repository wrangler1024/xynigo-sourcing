# 售后环境匹配与失败环境重试

状态：源码修复，尚未合并、部署或更新执行器。基线 `130475f`，开发分支 `codex/after-sale-env-recovery`。

## 问题与变化

按环境提交原先先完整读取 Hub 团队环境清单，再初始化环境结果。该阶段耗时时，页面只有默认排队占位。现在先发布“匹配环境中”的环境结果，并说明尚未读取订单或提交；匹配完成才进入正常环境队列。

正式 Hub 适配器新增可中止的分页迭代：每页最多 200 条，单次请求超时不超过 10 秒，分页预算 45 秒，关闭本次查询的额外重试和端口恢复。售后定位遇到全部精确序号/ID 后即停止，不再下载后续无关分页。按名称仍需读完清单以检测重名。此方案使用已有 `/env/list` 契约，不猜测服务端未确认的序号过滤参数；目标处于很后面的分页或 Hub 本身响应慢时仍可能超时，不能承诺所有查询立即完成。其他模块原 `env_list` 行为不变；售后扫描、回访等共用定位也受益于有界迭代。

按环境匹配超时或失败时，为各环境保留可见失败原因；匹配期间停止则标为已停止，均不打开订单或发起提交。运行状态和提示沿用既有云端字段，无协议扩展。

新增“重试失败环境”入口，与“补提失败单”分开。仅在本批次已结束、环境为 fail/login/inuse、该环境没有任何订单明细，且四个订单/提交计数都明确为数字零时开放。未知计数、已处理环境、已产生明细及结果待核对的批次不提供此入口。确认后只把选出的失败环境组成新批次，沿用统一建 Run、能力检查、幂等键和写入闸门，并记录来源批次。原订单补提逻辑不变。
