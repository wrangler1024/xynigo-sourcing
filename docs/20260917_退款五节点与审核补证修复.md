# 退款五节点与审核补证修复（代码完成，未发布）

基线 bc8a54b（v0.18.6 云端请求头修复之后）。本候选未部署、未分发桌面包。

## 问题与行为

旧读取器从整页截取文本并按关键词推断阶段；审核文案变体没有匹配时，会命中尚未开始的处理中标题。审核未通过的文案变体也未覆盖。前端固定四节点，无法区分 SHEIN 退款成功与金融机构处理。

新读取器仅接受退款身份一致、五个节点标题与状态序列完整且当前节点稳定的页面。已完成、当前与等待标记冲突时返回本次未确认，不以全文兜底。折叠的未来节点仍参与结构检查，但其文字不参与当前结果判断。仅原路退款的已验证五节点结构被识别，其他结构保守返回未确认。

正常阶段为 submitted / reviewing / processing / shein_refunded / bank_processed。审核节点有明确失败文案时返回 review_failed；同时存在可见、未禁用的真实补证按钮/链接才返回 evidence_required，显示“审核未通过 · 待补充凭证”。不把这种可重新审核的状态冻结为不可回访终态。旧 refunded/rejected 无法还原具体节点，保留历史事实并提示重新回访，不能冒充金融机构处理完成。

原因优先读取当前节点；必要时只读打开“Historial de negociación”。协商记录须匹配退款单号，采用最新完整时间事件的明确拒绝理由；新用户补证/重新申请、相同时间冲突、退款单归属冲突或任何未完整解析事件时不沿用旧拒绝理由。当前节点保留换行，避免将按钮文字并入理由。历史不决定当前阶段。未取得理由时明确显示原因尚未取得，不猜测。不会上传凭证、取消退款或重新提交。

## 三端与展示

新增有界 phaseEvidence：source / step / title / detail / canSupplement / reason / reasonSource。只传当前节点与确认理由，不传整页或完整时间轴。提交凭证及回访投影均保留；提交历史保留提交时凭证，不被后续回访改写。

迁移 0043_after_sale_phase_evidence 为跟踪表新增可空 phase_evidence 与 note。成功回访替换阶段及说明；失败读取保留上次有效阶段、原因与 checkedAt。仅身份及环境来源明确相同的历史观察可冻结到本次失败行；无历史事实也作为确定的空快照保存。失败进度/终态重传沿用原任务快照，不回写其他批次随后更新的共享状态。前端明确区分“本次状态未确认”和“上次成功读取”，旧倒计时不继续展示为当前倒计时。

前端改为五节点，审核异常停在第二节点，醒目标记并提供待补充凭证、审核未通过、本次未确认筛选；异常筛选包含上次保留状态并明确其时效。平台依据可展开。Excel 对等待、运行、停止和失败均区分本次执行状态与上次成功阶段，阶段与原因保持一致，导出范围仍为本批全部结果。
