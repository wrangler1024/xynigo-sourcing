# 采购协作导入云端化 P0

更新时间：2026-08-26

状态：共享测试环境已部署并启用；真实飞书目标表追加、图片和写后回读已通过，生产环境未部署。

## 目标

将“小犀助手 → 采购协作导入”从员工电脑的本地执行器迁移到 Xynigo 云端工作台。迁移完成后，员工可直接在云端完成店小秘 xlsx/XYP2 解析、图片预览、Excel 下载、普通飞书电子表格校验和二次确认导入，不再要求本机运行 Xynigo 或安装 `lark-cli`。

本功能只处理采购协作导入，不接 HubStudio、CDP 或 SHEIN 浏览器。本地执行器仍负责必须在采购电脑执行的外部环境与浏览器动作。

## 当前实现

### 单一解析算法来源

- 业务解析、XYP2 校验、稳定导入批次、表头契约、幂等续传和 Excel 生成继续以 `src/purchase_tool/procurement_import.py` 为唯一来源。
- `cloud/auth-service/deploy/sync_procurement_import_core.py` 将解析器与 Excel 单元格图片模块同步到云端包，只替换飞书访问适配器。
- 合成测试会逐字节检查云端副本与本地源一致，避免两套解析逻辑长期分叉。

### 云端飞书身份

- 云端使用“小犀代采”企业自建应用的 `tenant_access_token` 调用普通电子表格 OpenAPI。
- 不保存员工的飞书 `user_access_token` 或 refresh token；现有飞书登录继续只负责识别 Xynigo 用户。
- 目标电子表格必须显式添加“小犀代采”为可编辑文档应用，应用必须开通 `sheets:spreadsheet`。
- 用户仍可每批粘贴新的官方 `/sheets/` 链接；系统不硬编码表格 token、工作表 ID 或名称。

官方依据（查询日期：2026-08-26）：

### 加密短时计划

新增 `procurement_import_plans`：

- 按 `tenant_id` 和创建用户隔离。
- 解析后的采购明细、完整收件信息、采购链接和内嵌图片全部放在应用层加密载荷中。
- 使用部署 Fernet 密钥材料派生独立 AES-256-GCM 密钥，关联租户 ID 和计划 ID 作为认证附加数据。
- 默认有效期 30 分钟；过期后清空密文，只保留无敏感内容的计数与状态。
- 每个租户默认最多同时保留 5 个有效计划，防止大文件占满数据库和内存。

原始 xlsx 不作为普通文件落盘；云端保存的是压缩、认证加密后的短时解析计划。

### 持久化导入任务

新增 `procurement_import_jobs`：

- 持久化任务状态、行数、图片数、链接数和安全错误码。
- 订单号、收件人、地址、电话、采购链接和逐行错误详情不进入任务进度 JSON 或业务日志。
- 同一租户、目标工作表和稳定导入批次同时只允许一个非终态任务，数据库使用部分唯一索引兜底并发双击。
- Worker 单线程领取任务；服务重启后把中断任务恢复为 queued，再利用原有行签名、导入批次和写后回读逻辑安全续传。
- 真实飞书写入仍要求页面二次确认，未传 `confirmWrite=true` 时后端返回冲突错误。

### 云端 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/assistant/procurement-import/parse` | 上传并解析 xlsx，创建加密短时计划 |
| GET | `/v1/assistant/procurement-import/image` | 按计划与明细索引读取订单商品图 |
| GET | `/v1/assistant/procurement-import/export` | 生成并下载采购共享协作表 Excel |
| POST | `/v1/assistant/procurement-import/target/inspect` | 以应用身份只读获取工作表清单 |
| POST | `/v1/assistant/procurement-import/target/validate` | 读取并校验采购需求区和系统追踪区 |
| POST | `/v1/assistant/procurement-import/sheet-sync` | 二次确认后创建持久化导入任务 |
| GET | `/v1/assistant/procurement-import/sheet-sync/status` | 查询导入进度 |

所有接口要求有效 Xynigo 会话与 `assistant.access`。Cookie 鉴权写请求继续要求 `X-Xynigo-Web-CSRF: same-origin`。

### 前端适配

- 本机模式继续调用 `/api/assistant/procurement-import/*`。
- 云端模式自动映射为 `/v1/assistant/procurement-import/*`。
- 图片预览和 Excel 下载在云端使用同域 HttpOnly Cookie，不把会话令牌写入 URL 或 JavaScript。
- 云端解析计划文案明确标注“加密保存并到期自动清除”。

## 功能边界与保守策略

- 云端 P0 继续支持动态表头、追加、日期格式、冻结、行高、采购超链接和单元格图片。
- 官方普通表格 OpenAPI 没有提供与本机 `lark-cli +cells-get --include style` 等价的背景色读取契约。云端只给本次新追加行设置订单分组底色；对服务启动前已存在的行一律保留，避免覆盖采购员手工任务颜色。
- 云端 P0 不新增或覆盖表头批注；已有批注继续保留。表头值、分区颜色、冻结状态和行高仍会规范。
- 已导入订单不支持通过重新导入修改。跨批次完全一致的历史订单即使已有多个完整副本，也只按“已存在”整单跳过，不再修改其业务字段、链接、图片或任务底色；本次明细与历史不同、历史副本不完整或状态不确定时，在追加任何新行前停止。
- “采购任务认领前可由原提交运营修订”属于 PostgreSQL 采购任务和店小秘插件的独立状态流程，不是普通采购协作表导入能力；两者不得共用“修改”语义。
- 应用无表格权限、目标未添加文档应用、保护区域或飞书限流都会 fail closed；不确定结果依靠导入批次与行签名回读，不直接标记成功。
- 解析和导出不写外部系统；只有 `sheet-sync` 二次确认会修改飞书普通电子表格。

## 配置

```text
XYNIGO_AUTH_PROCUREMENT_IMPORT_ENABLED=false
XYNIGO_AUTH_PROCUREMENT_IMPORT_PLAN_TTL_SECONDS=1800
XYNIGO_AUTH_PROCUREMENT_IMPORT_WORKER_INTERVAL_SECONDS=2
XYNIGO_AUTH_PROCUREMENT_IMPORT_MAX_ACTIVE_PLANS_PER_TENANT=5
```

功能开关默认关闭。启用时必须已经配置应用层加密密钥；否则服务启动配置校验失败。

Nginx 只对 `/v1/assistant/procurement-import/parse` 放宽至 30 MiB，请求契约仍限制解码后的 xlsx 不超过 20 MiB。其他 API 继续保持 1 MiB 全局上限。

## 回滚

- 立即关闭 `XYNIGO_AUTH_PROCUREMENT_IMPORT_ENABLED` 可停止新解析与 Worker，不影响其他云端功能。
- 未写真实表前可直接回退应用镜像。
- 数据库降级到 `0013` 会删除两张短时计划/任务表；执行降级前必须确认没有 queued/running 任务并先做备份。
- 飞书已写入数据不能通过数据库降级自动撤销；canary 必须使用独立脱敏表，任何人工清理需另行确认。
