## 1. 结论

Xynigo 下一阶段固定采用“云端 Web 唯一用户入口 + 本地执行器主动出站通信”的产品形态：

1. 用户只在 `https://xynigo.samforo.icu` 登录、查看设备、修改本机配置、发起任务和查看进度。
2. 本地执行器不开放公网入站端口，只通过 HTTPS 443 主动连接云端。
3. 首期通信使用服务端可中断的 20–25 秒长轮询，不强制 WebSocket。
4. 配置继续以各电脑的 `config.json` 为本机事实源；云端通过短时配置指令读取和修改，不保存包含敏感值的完整副本。
5. 业务任务使用云端持久化任务、租约、幂等键、续租和结构化结果；HubStudio/CDP/SHEIN 副作用仍只在采购电脑执行。
6. 现有 `LocalTaskCoordinator`、HubStudio 请求闸门和安全并行规则继续作为执行器最后一道本地门禁，云端调度不能绕过。
7. `--local-ui` 和双平台“启动-本地执行器”入口在灰度期保留为回滚通道，不再作为普通用户主入口。
8. 当前按团队内部不超过 50 人设计，单套云端 API + PostgreSQL + HTTPS 长轮询足够，不提前引入 Redis、Kafka、专用消息队列或独立连接网关。
9. 通信协议与传输方式必须解耦：设备身份、任务租约、幂等、回执和业务处理器不依赖长轮询实现，为未来 WebSocket 和多实例扩展保留稳定接口。
10. WebSocket 未来首先作为“任务可用通知”通道，任务事实、领取、租约和最终结果仍由 PostgreSQL 与现有任务 API 裁决；WebSocket 断线时自动降级到长轮询。

不采用“云端网页直接请求 localhost”作为主方案。公网网页访问本地网络会受到浏览器 Local Network Access 权限、CORS、企业策略和跨浏览器差异影响；项目既定架构也要求通过云端设备心跳判断执行器状态，而非扫描或直连本机端口。

### 1.1 2026-08-27 实现进度

已实现：5 分钟一次性配对码、设备凭证摘要、Keychain/CurrentUser DPAPI、安全状态文件、设备撤销、最长 25 秒长轮询、60 秒在线窗口、45 秒租约、15 秒续租、配置读写、expected revision 双重校验、任务事件、重复完成回执幂等、写任务断线转 `uncertain`、Web 设备/配对/配置页面和绿色包配对入口。

## 2. 当前问题

### 2.1 产品入口与能力脱节

`v0.12.4` 起默认启动器打开云端 Web，但云端页面的本机接口仍由 `cloudLocalStub()` 返回占位数据。本机配置、采购员名单、HubStudio 分组和任务状态没有设备通道承接，因此出现以下问题：

- 云端设置页显示页面默认值，却不能读取真实 `config.json`。
- 采购员名单为 `buyers: []`，合法模板 `1:新刚` 被误判为名单外成员。
- 云端显示“执行器离线”，即使本机进程实际已经启动也无法可信关联。
- 物流查询、建环境和未来下单只能退回本机兼容页面执行。
- 云端和本机分别轮询自己的状态，缺少统一任务 ID、设备身份和审计链路。

### 2.2 当前轮询方式的问题

- Web 页面存在多个固定周期轮询点，任务状态曾使用约 1.5 秒间隔；空闲和后台标签页仍可能产生无价值请求。
- 登录轮询、任务轮询和模块轮询过去出现过竞争，受保护接口 401 曾误清理登录流程。
- 本地执行器没有统一云端长连接或长轮询；业务结果依靠功能完成后的独立上报队列，不能承担云端任务分发。
- 没有租约时，断网、进程重启和云端重启无法区分“任务未执行”“正在执行”“副作用已发生但结果未回报”。

## 3. 目标与非目标

### 3.1 本期目标

- 云端 Web 查看并选择当前用户有权管理的本地执行器。
- 完成一次性设备配对、可撤销设备凭证、心跳和能力上报。
- 云端读取和保存指定设备的本地业务配置。
- 建立通用任务、租约、幂等、进度、取消和结果协议。
- 把物流查询、买家号建环境和备用/测试环境作为首批本地任务类型接入。
- 优化执行器长轮询与 Web 状态轮询，降低空闲请求并避免重复在途请求。
- 形成跨设备、跨租户、断网、重启和撤销的合成验收闭环。

### 3.2 明确非目标

- 本期不部署生产环境，不把共享测试原地升级为生产。
- 不强制使用 WebSocket；只有长轮询实测不满足延迟或规模时再升级。
- 不自动启动或登录 HubStudio，不静默安装/升级本机程序。
- 不因通信通道完成自动开放真实 SHEIN 下单、付款或环境删除。
- 不把 App Secret、Cookie、密码、设备长期凭证或代理链接明文写入普通任务表和日志。
- 不删除本地兼容入口，不在同一版本号下替换已发布包内容。

### 3.3 使用规模与当前容量基线

Xynigo 已确认为团队内部系统，现阶段用户与持续在线执行设备均按不超过 50 个设计。在 20–25 秒空闲长轮询下，50 台在线设备约产生每秒 2–2.5 次空闲请求；已有请求上有任务时会立即返回，任务调度延迟不等于轮询超时时间。

当前容量策略固定为：

- 云端 API 保持无状态业务接口，PostgreSQL 保存设备、任务、租约、事件与采购事实。
- 每台设备只允许一个有效空闲 poll，正常超时后立即续接，异常时使用带 jitter 的指数退避。
- Nginx 超时高于应用长轮询超时，连接数、请求延迟、租约过期和重连率纳入监控。
- 不把团队人数增长本身作为引入复杂中间件的理由；只有指标证明单实例连接路由、异步吞吐或事件留存形成瓶颈时才升级。
- 内部自签名安装包只面向受控团队设备，签名信任范围、SHA-256、版本和发布渠道必须在云端目录明确标注，不扩大为公共可信发布承诺。

## 4. 总体架构

```text
浏览器 / 云端 Web
        │ 同源 HTTPS + HttpOnly Cookie + CSRF
        ▼
云端 API / RBAC / 租户隔离
        │
        ├── 设备服务：配对、心跳、能力、撤销
        ├── 任务服务：排队、租约、幂等、进度、接管
        ├── PostgreSQL：设备、任务、事件、配置修订号
        └── 脱敏审计：操作人、设备、结果、traceId
        ▲
        │ 本地执行器主动 HTTPS 长轮询；无公网入站
        │
本地执行器
        ├── Keychain / CurrentUser DPAPI：设备凭证
        ├── config.json：本机配置事实源
        ├── LocalTaskCoordinator：任务兼容与资源预占
        └── HubStudio Local API / CDP / SHEIN
```

## 5. 设备身份与配对

### 5.1 配对流程

1. 已登录用户在云端“设备管理”创建一次性配对码。
2. 云端只保存配对码摘要、租户、创建人、有效期和单次消费状态；建议有效期 5 分钟。
3. 本地执行器输入或接收该配对码，生成设备 ID、设备密钥对和安全元数据。
4. 执行器调用配对接口，提交一次性码、设备公钥、平台、客户端版本和能力目录。
5. 云端绑定租户/用户/设备并签发随机设备凭证；数据库只保存凭证摘要。
6. 设备凭证写入当前用户的 macOS 钥匙串或 Windows CurrentUser DPAPI，不进入 `config.json`。
7. 配对码立即失效；后续只使用设备凭证访问执行器专用接口。

### 5.2 设备权限

建议新增权限：

| 权限码 | 用途 |
|---|---|
| `executor.device.read` | 查看当前租户设备和在线状态 |
| `executor.device.pair` | 创建配对码并绑定设备 |
| `executor.device.revoke` | 撤销设备凭证和未开始任务 |
| `executor.config.read` | 读取设备公开配置 |
| `executor.config.write` | 修改设备本地业务配置 |
| `executor.task.dispatch` | 向设备派发已批准的本地任务 |
| `executor.task.cancel` | 请求取消尚可安全停止的任务 |

设备凭证不是用户会话，不能访问成员管理、采购详情、完整买家号列表或其他普通业务 API。设备只允许：配对完成后的心跳、领取本设备任务、续租、进度和结果上报。

### 5.3 设备撤销

- 管理员撤销设备后，服务端立即让设备凭证失效。
- 下一次轮询返回稳定错误 `executor_revoked`；执行器停止领取任务并清理内存凭证状态。
- 未领取任务取消；已执行任务根据是否产生外部副作用进入 `cancelled`、`failed` 或 `uncertain`，不得统一改回 `queued`。

## 6. 长轮询通信协议

### 6.1 空闲长轮询

执行器使用单独通信线程调用：

```http
POST /v1/executor-channel/poll
Authorization: Bearer <device-credential>
Content-Type: application/json
```

请求摘要建议包含：

```json
{
  "protocolVersion": 1,
  "clientVersion": "0.13.0",
  "capabilities": ["config.v1", "logistics.v1", "environment-create.v1"],
  "configRevision": "sha256:...",
  "availableSlots": 1,
  "runningTasks": [],
  "hubStatus": "ready"
}
```

服务端行为：

- 有兼容任务时立即尝试加锁并返回一条租约任务。
- 无任务时最多保持请求 20–25 秒，再返回空响应和服务端时间。
- 每次有效 poll 同时更新设备 `last_seen_at`，不再另设高频空闲心跳。
- 服务端超时应短于 Nginx/read timeout；建议 Nginx 60 秒、应用长轮询 25 秒。
- 每个设备只允许一个有效空闲 poll；重复 poll 使旧请求安全结束或返回 `poll_already_active`。

### 6.2 重连退避

| 场景 | 策略 |
|---|---|
| 正常空响应 | 立即发起下一次长轮询 |
| 网络断开/超时 | `1s → 2s → 4s → 8s → 16s → 30s`，加入 0–20% jitter |
| HTTP 429 | 使用 `Retry-After`，最少 2 秒、最多 60 秒 |
| HTTP 401/403 | 停止轮询，区分凭证失效、设备撤销和成员停用 |
| 协议不兼容 | 停止领取并提示必须升级客户端 |
| 云端恢复 | 成功一次后退避立即清零 |

该策略将空闲执行器请求控制在约 2–3 次/分钟，同时任务可在已有长轮询请求上即时返回，调度延迟不等于轮询周期。

### 6.3 运行中续租与进度

- 执行线程与通信线程分离；业务任务不能阻塞设备续租。
- 默认租约 45 秒，执行器每 15 秒续租一次。
- 只有状态、阶段或计数变化时才上报进度；无变化时只续租，不重复写同一进度事件。
- 高频明细合并上报，建议最快每 2 秒一次、每次包含累计计数，不逐行刷云端。
- 服务端使用 `task_id + lease_token + attempt` 校验续租和结果，旧 attempt 的晚到结果必须拒绝或标记 superseded。
- 执行器收到取消请求后只设置本地停止信号；当前不可中断外部步骤完成后再停，不能强杀导致结果未知。

## 7. Web 端轮询优化

### 7.1 统一轮询调度器

把分散的 `setInterval` 改成一个 `CloudPollingScheduler`：

- 所有受保护轮询在 `authReady=true` 后注册，退出或锁屏后统一停止。
- 同一 endpoint 同一时刻只允许一个请求，后续触发合并为一次 single-flight。
- 使用 `AbortController` 在切换租户、退出、页面销毁时取消旧请求。
- 使用 Page Visibility API 动态降频；后台标签页不刷新高频业务状态。
- 请求失败使用退避，不让多个模块同时形成错误风暴。
- 页面只在对应模块可见或存在运行任务时订阅该模块的详细状态。

### 7.2 建议频率

| 状态 | 云端 Web 轮询间隔 |
|---|---:|
| 登录进行中 | 2 秒，最多 5 分钟，独立于业务轮询 |
| 当前设备存在运行任务 | 2 秒 |
| 设备在线、无任务、页面前台 | 15 秒 |
| 页面后台 | 60 秒 |
| 执行器离线 | 10 秒持续 1 分钟，随后 30 秒 |
| 配置保存等待确认 | 1 秒，最多 30 秒，随后明确超时 |

云端可提供合并摘要接口，减少 Web 同时请求设备、任务和配置状态：

```http
GET /v1/executors/{executorId}/runtime-summary
```

响应只包含设备在线状态、客户端版本、能力、当前任务摘要、配置修订号和 HubStudio 状态；不返回原始配置、凭证或任务敏感载荷。

### 8.2 任务状态机

```text
queued → leased → running → succeeded
   │        │         ├── failed
   │        │         ├── uncertain → manual_review → resolved
   │        │         └── cancelled
   │        └── lease_expired → queued（仅无外部副作用任务）
   └── expired / cancelled
```

关键规则：

- `config.read` 可安全重新排队。
- `config.write` 只有在 `expectedRevision` 未变化且相同幂等键时才可重试。
- 物流查询属于只读任务，可在确认本地浏览器已关闭后重新领取。
- 建环境、登录、付款、删除环境等外部副作用任务在结果未知时必须进入 `uncertain`，先探测/接管，禁止自动重复执行。
- 所有状态转换由数据库条件更新或行锁完成；客户端不能直接指定任意终态。

## 9. 本机配置读取与保存

### 9.1 配置事实源

- `config.json` 继续保存在每台电脑的安装目录，在线更新继续原样保留。
- 云端只持久化 `config_revision` 和更新时间；配置读取结果作为短时任务结果返回，超时清理。
- 读取使用现有 `public_config()`，代理链接只返回“已配置/默认来源”，不回显原值。
- 写入复用现有 `updated_config()`、业务名单校验、任务运行门禁和 `save_config()` 原子替换。

### 9.2 配置保存流程

1. 用户在云端选择在线设备。
2. Web 创建 `config.read` 任务并读取当前 `configRevision`。
3. 用户编辑并提交 `config.write`，请求带 `expectedRevision` 和幂等键。
4. 云端确认设备在线、权限满足且没有同设备未完成配置写任务。
5. 执行器领取任务，先重新读取本机修订号。
6. 修订号不一致返回 `config_revision_conflict`，不覆盖文件。
7. 执行器本地校验；若运行任务涉及端口、并发或并行模式，返回 `executor_busy`。
8. 原子写入成功后按需要重连 HubStudio 客户端，计算新修订号并回报。
9. 云端页面只有收到设备确认后才显示“已保存到某某电脑”。

### 9.3 敏感字段

第一阶段普通配置指令支持：

- `hubPort`
- `concurrency`
- `safeParallelTasks`
- `hiddenQueryColumns`
- `verifySampleCount`
- `envCreateWorkers`
- `importBuyerPlan`
- `purchaseSite`
- `purchaseTags`

`proxyLink` 保持只写不回显。若允许从云端修改，浏览器应使用设备公钥进行端到端加密，AAD 至少包含 `tenant_id / executor_id / task_id / expectedRevision`；云端任务表只保存密文信封。飞书 App Secret 继续走本机钥匙串/DPAPI 的专用凭证流程，不并入普通配置任务。

离线设备不允许排队保存配置，避免数小时后意外覆盖用户已经在本机修改的新值。

## 10. 首批业务任务接入

### 10.1 任务类型

| 类型 | 本地 kind | 副作用 | 自动重试 |
|---|---|---|---|
| `logistics.query.v1` | `query` | 只读浏览器查询 | 受控允许 |
| `environment.create-bound.v1` | `env_batch` | 创建环境、导 Cookie、绑号、备注 | 结果未知时禁止 |
| `environment.create-backup.v1` | `backup_env` | 创建环境、备注 | 结果未知时禁止 |
| `config.read.v1` | `config_read` | 无 | 允许 |
| `config.write.v1` | `config_write` | 本机配置落盘 | 按修订号幂等 |

### 10.2 安全并行

- 云端调度器根据设备 `availableSlots`、能力和活动租约做第一层筛选。
- 允许的首期组合保持现有规则：一批物流查询 + 一批买家号建环境，或一批物流查询 + 一批备用/测试环境。
- 两个物流批次、两个环境创建批次、注册与其他任务继续互斥。
- 云端任务载荷包含规范化资源键；执行器仍调用 `LocalTaskCoordinator.begin/reserve/finish` 做最终原子校验。
- HubStudio Local API 总并发、0.3 秒请求错峰、`E010205` 共享冷却和浏览器启动/停止串行门禁保持不变。
- 安全并行开启时建环境 worker 继续自动封顶为 3。

## 12. 可靠性与故障处理

| 故障 | 处理 |
|---|---|
| 执行器离线 | Web 显示最后在线时间，本机设置和任务按钮禁用 |
| 云端短时断网 | 执行器退避重连；运行任务继续本地执行并持久化安全进度 |
| 执行器重启 | 恢复本地任务快照；按 task/attempt 与云端协调，不盲目重做外部步骤 |
| 云端重启 | PostgreSQL 保留任务和租约；启动后扫描过期租约 |
| 续租超时 | 只读任务可回队列；外部副作用任务转 `uncertain` |
| 重复完成上报 | 相同 attempt 幂等返回原结果；旧 attempt 标记过期 |
| 配置冲突 | 返回 `config_revision_conflict`，要求页面重新读取 |
| 设备撤销 | 下一 poll 失败并停止领取；正在执行任务进入人工判断 |
| 版本太旧 | 能力不匹配，不派发任务；云端提示升级 |

执行器需要新增本地非敏感任务状态文件，只保存任务 ID、类型、attempt、幂等键、阶段和脱敏进度；不得保存云端设备凭证、买家号密码、Cookie、代理链接或完整业务载荷。

## 13. 安全与审计

- 所有通信使用 HTTPS 443 出站；本地执行器不开放公网端口。
- 用户会话与设备会话完全分离，数据库只保存会话/凭证摘要。
- 配对码短时、单次使用、摘要存储，并限制创建和交换频率。
- 设备 API 固定租户和设备范围，跨租户统一返回不可见。
- 配置字段和任务类型使用服务端白名单，禁止任意函数名、命令、文件路径或脚本执行。
- 云端创建任务记录创建人、角色快照、设备、任务类型、结果、稳定错误码和 traceId。
- 本地 HubStudio/SHEIN 原始响应、页面 HTML、堆栈和凭证明文不得进入云端日志。
- 高敏配置写入需要独立权限；浏览器端密文信封不得在前端控制台打印。
- 设备时间只作展示；租约、过期和排序全部以云端数据库时间为准。

## 14. 前端改造

### 14.1 全局设备状态

顶部状态区从本机 stub 改为云端设备摘要：

- `本机已就绪 · 志恒的 Windows 采购机`
- `执行器在线，HubStudio 未连接`
- `执行器离线 · 最后在线 2 分钟前`
- `客户端版本过低，需要升级到 v0.13.0`

多设备用户必须显式选择目标设备；最近使用设备只作默认选择，不得静默向另一台在线电脑派发任务。

### 14.2 设置页

- 页面进入时创建 `config.read`，收到真实配置后才开放编辑。
- 显示设备名称、平台、客户端版本、配置修订号和读取时间。
- 保存按钮文案为“保存到「设备名」”。
- 执行器离线、读取超时、任务运行冲突或修订冲突必须显示不同错误。
- 删除 `cloudLocalStub('/api/config')` 的可编辑占位行为；没有设备时不填充看似真实的默认值。

### 14.3 任务页面

- 物流查询和环境创建统一通过云端创建任务，不直接调用本机 `/api/*`。
- 页面展示云端任务 ID、目标设备、租约状态、阶段、完成数量和稳定错误码。
- 用户取消只表示请求安全停止；页面不能把“已请求取消”误显示为“已取消”。
- `uncertain` 使用醒目人工接管状态，禁止出现“自动重试”按钮。

## 15. 面向复杂使用场景的可扩展方向与目标

### 15.1 扩展原则

未来扩展只替换通信和运行基础设施，不重写采购业务协议。以下契约必须保持稳定：

- PostgreSQL 始终是设备任务、采购事实、租约和最终状态的事实源。
- `protocolVersion / messageId / taskId / leaseToken / attempt / idempotencyKey / traceId` 保持传输无关。
- 长轮询长期保留为默认或断线降级通道；不能因启用 WebSocket 让设备失去恢复路径。
- WebSocket、Redis 或消息队列只传递通知和可重建事件，不成为不可恢复的唯一任务存储。
- 外部副作用任务继续遵守人工确认、租约、幂等探测和 `uncertain` 接管，实时连接不能绕过安全门禁。
- 用户会话、设备凭证和插件短期会话继续分域，任何新传输层都不能扩大凭证权限。

### 15.2 传输适配层目标

执行器与云端应形成统一传输抽象：

```text
ExecutorTransport
├── LongPollingTransport       当前默认 + 永久降级
└── WebSocketTransport         未来按需启用

业务协议
├── task_available             仅通知
├── task_lease / lease_renew   领取与续租
├── task_progress              脱敏进度
├── task_result                幂等结果
└── heartbeat / capability     状态与能力
```

首期 WebSocket 不直接承载完整敏感任务载荷，只发送 `task_available` 等轻量通知。执行器收到通知后仍通过现有 HTTPS 接口领取任务；通知丢失时，长轮询或恢复扫描仍能发现 PostgreSQL 中的任务。

### 15.3 分级演进路线

| 等级 | 触发条件 | 新增能力 | 保持不变 |
|---|---|---|---|
| L0 当前轻量架构 | ≤50 台设备、任务低频、长轮询指标健康 | HTTPS 长轮询、单实例 API、PostgreSQL 租约 | 全部现有协议 |
| L1 实时通知增强 | 出现亚秒级任务通知、高频状态或实时日志需求 | WebSocket 通知；长轮询自动降级 | PostgreSQL 任务领取、租约、幂等和回执 |
| L2 云端多实例 | 单实例连接数、发布维护或可用性要求需要水平扩展 | 实时连接网关；Redis Pub/Sub 仅用于跨实例设备通知 | PostgreSQL 继续保存任务事实，不使用 Redis 保存最终任务状态 |
| L3 异步业务扩展 | 飞书投影、外部回调、重试、对账形成独立吞吐压力 | Outbox Worker 池、独立并发与失败队列、可重放对账 | 采购事务先入 PostgreSQL，外部结果写后回读 |
| L4 大规模事件平台 | 事件吞吐、长期留存和多消费者需求经指标证实 | 再评估持久消息队列或 Kafka 类事件平台 | 不为预期规模提前建设 |

### 15.4 升级触发指标

出现以下任一情况时才进入对应架构评审，不能仅凭“未来可能需要”升级：

- 长轮询任务派发 P95 持续不满足目标，且瓶颈确认在传输层而非数据库或业务执行。
- 在线连接需要跨多个 API 实例路由，滚动发布频繁造成设备集中断连。
- 高频状态、实时日志或协作事件要求服务端主动连续推送。
- 飞书、物流或对象存储投影的排队时间、失败重试量明显影响主事务 API。
- 单一 PostgreSQL 写入、索引或任务扫描成为经监控确认的瓶颈。
- 产生多个独立事件消费者，并明确要求事件长期留存、顺序消费或重放。

### 15.5 未来目标架构

目标不是把当前系统一次性改造成重型平台，而是形成以下可渐进组合：

```text
云端 Web / 双插件
        │
        ▼
无状态控制面 API ───── PostgreSQL 事实源 ───── Outbox Worker
        │                      │                    │
        │                      └── 审计 / 对账      └── 飞书 / 物流 / 对象存储
        │
        ├── HTTPS 长轮询（默认与降级）
        └── WebSocket 实时通知（按需）
                  │
                  └── Redis Pub/Sub（仅多实例时）
        │
        ▼
本地执行器 ───── HubStudio / CDP / SHEIN
```

配套可探索架构图：[`Xynigo未来复杂场景可扩展架构_20260827.html`](Xynigo未来复杂场景可扩展架构_20260827.html)。该图将当前能力和未来按需组件分区展示，不能把虚线未来组件解释为已部署能力。

## 17. 验收指标

### 17.1 功能验收

- 云端能显示指定电脑旧配置，采购员名单不为空。
- 云端勾选安全并行并保存后，本机 `config.json` 实际变化。
- 重启执行器后配置仍生效，云端读取修订号一致。
- 一个用户有两台设备时，配置和任务不会发错设备。
- 设备撤销后下一次 poll 立即失败，不能继续领取。
- 物流查询 + 一批建环境保持既有安全并行规则。

### 17.2 性能与通信指标

- 空闲执行器：每分钟不超过 3 次 poll。
- 在线任务派发：P95 小于 2 秒。
- 在线配置保存：P95 小于 5 秒。
- 执行器离线判定：45 秒内。
- Web 后台标签页：每分钟不超过 1 次状态请求。
- 同 endpoint 在途请求数始终不超过 1。

### 17.3 故障验收

- poll 响应前断网、领取后断网、执行中断网、完成上报断网分别注入。
- 本地执行器、云端应用和 PostgreSQL 分别重启。
- 同一任务重复领取、旧 attempt 晚到、租约过期和用户重复点击分别覆盖。
- 外部创建返回成功但回读超时必须进入接管流程，不能再次 create。
- 所有日志、数据库任务摘要和测试夹具通过凭证扫描。

## 18. 部署、灰度与回滚

### 18.1 功能开关

- `XYNIGO_AUTH_EXECUTOR_CHANNEL_ENABLED=false`
- `XYNIGO_AUTH_CLOUD_LOCAL_SETTINGS_ENABLED=false`
- `XYNIGO_AUTH_EXECUTOR_BUSINESS_TASKS_ENABLED=false`
- 本地 `XYNIGO_EXECUTOR_CHANNEL_ENABLED=true`

上线顺序：迁移和后端关闭开关部署 → 新客户端发布 → 两台设备配对 → 开配置读取 → 开配置写入 → 开只读物流 → 开合成环境任务 → 单独批准真实写入灰度。

### 18.2 回滚

- 关闭云端通道开关后，不再创建或出租新任务。
- 撤销测试设备凭证并等待非终态任务归零或人工接管。
- 云端设置页退回只读“执行器通道暂不可用”，不得恢复空名单可编辑 stub。
- 本地 `config.json`、日志、运行数据和兼容入口保持不变。
- 数据库迁移为纯新增；除非确认设备和任务表为空且已备份，否则不执行降级删表。
- 回滚客户端使用绿色包备份机制，仍需用户确认，不远程静默替换。

## 19. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 旧客户端无法连接 | 能力目录和最低版本提示；不开兼容任务 |
| 长轮询被代理提前断开 | 25 秒应用超时、60 秒网关超时、退避重连 |
| 多设备误派发 | 用户显式选设备；任务固定 executor_id |
| 配置被并发覆盖 | expectedRevision + 同设备配置写互斥 |
| 任务重复外部写入 | 幂等键、租约 attempt、本地探测/接管、uncertain |
| 凭证或代理泄漏 | 设备安全存储、摘要、密文信封、统一日志脱敏 |
| 通信线程影响业务线程 | 独立线程/队列；续租不依赖 UI 或业务主循环 |
| 云端状态与本机不一致 | 设备确认后才显示成功；服务端时间和修订号裁决 |

## 20. 最终完成定义

只有同时满足以下条件，才可宣布“云端 Web 已成为统一入口，本地执行器通信通道完成”：

1. Windows 与 macOS 各一台真实采购电脑完成配对、撤销和重新配对。
2. 云端读取旧配置、修改并写回本机，重启后保持一致。
3. 长轮询、续租、断网、重启、重复领取和旧 attempt 晚到全部通过故障注入。
4. 物流查询和环境创建在云端发起、本机执行、云端显示结构化结果。
5. 不确定外部结果进入人工接管，没有自动重复副作用。
6. Web 不再依赖可编辑的本机 stub，也不把 localhost 直连作为主要检测方式。
7. 审计能追踪用户、设备、任务和结果，且凭证扫描无明文泄漏。
8. 本地兼容入口、功能开关、设备撤销和数据库/客户端回滚均完成演练。

在上述门槛关闭前，云端设置和本地业务任务仍应标记为团队测试能力，不得解释为生产正式开放。
