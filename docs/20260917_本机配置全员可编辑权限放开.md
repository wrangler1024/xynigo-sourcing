# 本机配置向所有登录成员放开

分支 `codex/local-config-open-members`，提交 `d9b9049`（基于 origin/main `ab4c65a`）。按 Jeff 20260917 决策执行。

## 背景与诊断

志恒、康德在云端工作台是管理员，但桌面客户端「本机配置」显示"普通采购员仅可查看设备级设置"，运行参数与物流查询高级设置只读。原因是两条闸门叠加加一处硬编码文案：

- 桌面客户端 `canConfigure()` 要求 `super_admin` 角色且持有 `system.integration.manage`；该权限在云端属超管专属（`SUPER_ADMIN_ONLY_PERMISSIONS`），管理员结构性拿不到。
- 执行器本地写入端点同样要求 `super_admin`：POST `/api/config` 内联校验，`/api/hub-api-key` 经 `AUTH_PERMISSION_BY_PATH` 表驱动命中超管专属。
- 锁定态文案写死"采购员"，管理员看到后误以为角色未生效。侧栏头像旁角色字样才是真实角色。

## 决策

Jeff 拍板方案 B 并扩大范围：本机运行参数不设角色门槛，所有登录成员可配置。这些设置仅存本机、影响本机执行器行为，「发布本机配置到组织」仍为管理员流程，未改动。

## 改动（4 文件，+60/−15）

- `src/purchase_tool/main.py`：POST `/api/config` 改为仅登录校验；从 `AUTH_PERMISSION_BY_PATH` 移除 `/api/hub-api-key`，同样落到仅登录校验。`hub-core-repair` 保持超管专属不变。
- `src/purchase_tool/web/desktop.js`：`canConfigure()` 改为登录即可，本机配置页对全部成员解锁，锁定文案不再渲染。
- 测试：反转原"成员不可写"用例为"仅需登录"；`test_env_config.py` 新增成员真实保存运行参数与 HubStudio Key 两个成功用例。
