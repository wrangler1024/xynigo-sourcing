## 产品定位

Xynigo Sourcing 是面向跨境电商团队的采购协同与本地自动化系统。当前稳定能力运行在采购员电脑，通过本机 Web 页面调用 HubStudio Local API/CDP，并可通过企业自建应用读写飞书多维表格。

系统后续采用“云端控制面 + 本地执行器”形态，但当前尚未提供托管式云端控制面、飞书用户登录或多用户权限服务。

确认过的归属规则：

- 账号注册和环境创建继续归属资源中心。
- “采购协同”一级菜单统一命名为“采购中心”。
- 原“工具中心”暂定命名为“小犀助手”；没有具体需求前不显示空二级菜单。
- 成员、角色、权限和登录安全统一从系统管理进入。
- 运营中心、财务中心是独立一级模块，不并入采购中心。

## 已完成的前端决策

- 沿用 Xynigo 现有品牌、色彩、侧边栏和 Banner 视觉语言，不重新设计一套 UI。
- 一级和二级导航统一位于左侧边栏；一级菜单选中态不使用多层叠加效果。
- 二级业务页采用工作区多 Tab：最多同时打开 10 个，溢出时可横向滚动，并提供页签清单、关闭其他和关闭右侧。
- “规划”入口与“现有”入口必须明确区分；规划页不得使用伪造演示数据冒充已实现能力。
- 本轮验收范围是桌面端。移动端短期不开发，不作为本里程碑完成条件。
- `file://` 只能查看静态页面；完整运行必须使用启动窗口显示的 `http://127.0.0.1:<port>/` 地址。

## 当前后端事实

- 本地入口为 `purchase_tool.main`，使用绑定在 `127.0.0.1` 的 `ThreadingHTTPServer`。
- `main.py` 同时承担 HTTP 路由、进程级状态和任务编排装配，尚未拆分为版本化 API 层。
- 真实业务能力主要位于：
  - `shein_query.py`：订单和物流查询；
  - `buyer_library.py`：买家号库读取与号商账号入库；
  - `buyer_register.py`：买家号注册流程；
  - `env_batch.py`：采购/备用环境创建与出口 IP 验证；
  - `hub_api.py`、`cdp.py`：HubStudio Local API 和浏览器执行；
  - `lark_openapi.py`、`lark_ledger.py`：飞书 OpenAPI 与统一台账写回。
- 当前 API 没有用户会话、租户、角色或权限校验，只能安全地绑定本机回环地址，不能直接暴露到公网。
- 后台任务状态主要保存在进程内存；进程退出后不具备统一的云端任务恢复和审计能力。
- 飞书买家号库列表只返回脱敏字段；号商入库采用“本地解析 → 飞书只读查重 → 脱敏预览 → 单独确认写入”。
- 新建环境的出口 IP 验证使用 HubStudio 无头后台浏览器验证全部新建环境，不打开真实可见 Hub 窗口。

## 目标架构决策

目标链路如下，状态为“已确认方向、尚未实现”：

```text
飞书登录 / 外部业务服务
          ↕ HTTPS
   Xynigo 云端控制面
          ↕ 本地主动轮询（首期）/ WebSocket（后续）
   Xynigo 本地执行器
          ↕
HubStudio Local API / CDP
```

边界原则：

- 云端控制面负责身份、组织、权限、业务任务、分发、审计和外部服务集成。
- 本地执行器负责只有本机才能完成的 HubStudio/CDP 操作，不开放公网入站端口。
- 首期优先使用本地主动 HTTPS 轮询，待实时性和规模确有需要再增加 WebSocket。
- 飞书登录用于识别系统用户；企业自建应用凭证用于服务访问多维表格，两者是不同的鉴权域，不能混用。
- 前端只能通过 Xynigo 后端访问飞书，不直接持有飞书应用密钥或调用敏感写接口。
- 多用户并发后，交易状态和账号分配锁不能只依赖飞书表或单进程锁。云端数据库应成为工作流与权限的事实源，飞书作为协同视图和外部业务账本同步。
- 腾讯轻量服务器可承载首期单节点控制面，但正式开放前必须具备 HTTPS、备份、最小端口暴露、日志脱敏、凭证托管和恢复演练。

## 买家号与环境创建业务记忆

目标流程是“买家号先入库，再创建采购环境”：

1. 号商账号或未来自注册账号先进入买家号库。
2. 创建采购环境时只配置站点、环境数量、采购员分配等业务参数。
3. 后端从符合条件的可用买家号中分配并预占账号。
4. 本地执行器创建 HubStudio 环境、绑定账号/Cookie，并后台无头验证全部出口 IP。
5. 成功后写回绑定环境、采购员、状态和验证结果；失败时释放未使用预占，结果不确定时进入人工复核。

目前“买家号先入库”及现有环境创建已具备，但“按数量自动抽取、并发预占、超时释放”尚未实现，是资源中心后端的下一条核心业务链路。

## 不可破坏的安全约束

- 真实密码、Cookie、App Secret、访问令牌、代理链接和完整业务数据不得进入仓库、测试夹具、日志或截图。
- 所有真实平台写入必须保留明确确认；HubStudio 写入与飞书写入分别确认。
- 飞书写入必须先做字段/冲突预检，并在写后回读确认；不确定结果不能记为成功。
- API 错误和进度信息必须脱敏；公开配置接口不得回显 Secret、完整飞书链接、Base Token 或 Table ID。
- 后端权限必须作为最终裁决，隐藏前端菜单不能替代接口鉴权。
- 任务下发必须有幂等键、租约/超时、重试边界和审计记录，避免重复创建环境或重复写账。
