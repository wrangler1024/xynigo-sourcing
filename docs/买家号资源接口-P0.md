# Xynigo 买家号资源接口 P0

更新时间：2026-08-26

状态：数据库查询、完整账号凭证入库、下单绑定和数据库→独立 Base outbox 镜像已完成并部署到共享测试环境；资源中心页面已切换 PostgreSQL，不再读取旧飞书台账。迁移 `0012_buyer_account_credentials` 已生效，旧表 320 条真实测试记录（含账号、密码、Cookie、接码资料和业务字段）已一次性迁入 PostgreSQL，持续同步 Worker 已启用。

## 目标

为采购下单闭环提供可信的买家号选择与占用边界。页面和下单接口不再相信客户端提交的买家号引用或标签，而是提交云端生成的 `buyerAccountId`，由后端在同一数据库事务中回查、加锁、校验并转换为历史快照。

PostgreSQL 是完整买家号事实源：除稳定引用、站点、流程状态、来源、Hub 环境和同步状态外，还保存经 Fernet 认证加密封装的账号标识、手机号、密码、Cookie、接码 Key/链接和登录链接，以及迁移所需的业务资料。测试 Base 按用户明确授权保存同一份明文业务镜像，供采购协作；完整凭证不进入日志、错误详情、Outbox payload、Git 或测试夹具。飞书应用 Secret、数据库密钥和访问令牌仍不属于买家号业务数据，禁止写入 Base。

## 数据表

迁移 `0009_buyer_account_resource` 新增 `buyer_accounts`，并在 `checkout_attempts`、`purchase_batches` 增加 `buyer_account_id` 外键。迁移 `0011_buyer_db_base_mirror` 增加来源字段、Base 同步状态/记录 ID/时间，并允许买家号进入已有 `operational_sync_outbox`。迁移 `0012_buyer_account_credentials` 增加 `credentials_ciphertext` 和 `source_business_profile`；凭证明文只在已授权请求和 Worker 执行时于内存中解密。

核心约束：

- `tenant_id + account_ref` 唯一，买家号不能跨租户引用。
- `current_checkout_attempt_id` 唯一，一个买家号同一时刻最多归属一个下单尝试。
- 下单尝试同时保存 `buyer_account_id` 和当时的稳定 `account_ref/display_label` 快照；后续台账标签变化不改写历史批次。
- 流程状态为 `available / reserved / in_use / cleanup_pending / post_payment_hold / manual_review / disabled`；另存源台账可用性 `available / manual_review / disabled`，避免活动流程状态覆盖源停用信号。
- 凭证状态为 `ready / unverified / invalid / unknown`；只有“流程可用 + 源台账可用 + 凭证 ready”可进入下单候选。
- 付款成功进入 `post_payment_hold`，不会自动恢复可用；失败后只有完成环境清理且结果明确为可复用才释放。该门禁保留“成功买家号何时复用”的业务待确认项。

## 云端 API

### 查询买家号

`GET /v1/resources/buyer-accounts`

权限：基础列表需要 `resource.buyer.read`；请求完整凭证还需要 `resource.buyer.credential.read`。

查询参数：

- `site=US|MX`
- `status=<买家号状态>`
- `credentialStatus=<凭证状态>`
- `keyword=<账号标签、稳定引用、环境名或采购员>`
- `includeCredentials=true|false`（默认 `false`）
- `selectableOnly=true|false`
- `page`、`pageSize`（单页最多 200）

默认响应只返回流程元数据；资源中心买家号库和采购绑定页使用 `includeCredentials=true` 返回完整账号、手机号、密码、Cookie、接码资料、登录链接和来源业务字段。服务端对敏感读取做权限校验和只含数量/分页信息的审计，不记录字段值。只有流程状态、源可用性和凭证状态同时满足门禁的账号才可选择。当前本机同源代理为 `GET /api/cloud/buyer-accounts`，Bearer 会话仍只保存在本地 Python 服务。

契约使用 `extra=forbid`，只接受上面定义的嵌套凭证和业务字段，未知字段返回 422。凭证对象会先规范化再整体加密；Outbox 仅保存聚合 ID、版本和同步坐标，不保存明文。同步采用租户级串行、幂等 upsert，不因快照缺项删除或停用记录。`reserved / in_use / cleanup_pending / post_payment_hold` 等流程状态不会被台账刷新释放，仍归属下单尝试的记录也不会被覆盖站点和 Hub 绑定。

号商入库先调用 `POST /v1/resources/buyer-accounts/preflight`，按稳定账号引用和号商单号引用批量查重，再调用快照接口写完整数据。2026-08-26 已新建完全独立的飞书 Base「Xynigo 买家号资源同步测试表」；字段坐标与同步边界见 [`飞书买家号安全同步测试表.md`](飞书买家号安全同步测试表.md)。Base 不参与列表、查重、占用或下单裁决，只消费数据库同事务 outbox。

## 下单绑定变化

`CheckoutResourceBody` 现只接受：

```json
{
  "hubEnvironmentRef": "hub-us-0001",
  "hubEnvironmentName": "US-PUR-0001",
  "buyerAccountId": "00000000-0000-0000-0000-000000000001",
  "site": "US"
}
```

服务端处理顺序：

1. 锁采购单与目标买家号记录。
2. 验证租户、站点、买家号状态和凭证状态。
3. 验证 Hub 环境及买家号没有被其他活动尝试或成功批次占用。
4. 创建下单尝试并把买家号改为 `reserved`。
5. 开始结算后改为 `in_use`；失败进入清理/人工复核；付款成功进入 `post_payment_hold`。
6. 全部状态变更、采购数量占用和正式批次在 PostgreSQL 事务内提交，外部 HubStudio/SHEIN 动作仍由后续执行器任务完成。

主要错误码：

- `buyer_account_not_found`
- `buyer_account_unavailable`
- `buyer_account_credential_unavailable`
- `buyer_account_filter_invalid`
- `checkout_resource_site_mismatch`
- `checkout_resource_retained`
