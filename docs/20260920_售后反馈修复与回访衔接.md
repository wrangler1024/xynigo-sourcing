## 实现边界

- 无申请入口的订单只读取事实，不进入申请或资格提交路径。已有退款 `source=existing`，结果仍为跳过，不能记为新受理；统计标题改为“处理订单”。有申请入口时仍沿用既有提交前核验、幂等和停止保护。
- 动态清单提前可见后，停止或环境读取异常须收尾待处理行，避免终态仍显示排队。已存在的未知写入核对状态不被改为普通失败。
- 完整发现结果必须覆盖全部输入环境；部分失败、结果缺失、停止等情况不自动接续。手动继续只发送当前校验接受的退款身份，仍限制 500 单。
- 保留两阶段架构：发现用于确定范围，回访用于读取详情。阶段之间仍需身份校验、数量限制和执行器一致性检查。减少二次环境打开属于性能重构评估，本次不合并任务或改变部分范围的确认规则。
- 本页保留发现阶段商品图供后续回访显示；回访接口不增加商品字段。无既有商品快照的历史回访或页面刷新不能保证有图，不能把未采集事实补成已知。
- 新增字段均可选，使用既有数据库列。发布必须云端先行、执行器后行；仅更新 Web 不能修复旧执行器的数据丢弃。详见 [生态跨仓契约](生态跨仓契约.md)。
