# 采购售后反馈修复：实现与验证

日期：20260916。需求由用户确认并授权开发；候选分支 `codex/after-sale-feedback-complete`，基线 `4988b1d`。本记录描述本地开发结果，不代表云端或安装包已更新。

## 界面与采集

- 承接 `ddc8c42` 的已确认原型：可申请清单、提交结果、退款跟踪采用约 20 个标准行的最大容器高度；超过后滚动，表头固定，不截断数据。直接提交与指定回访输入框和按钮同高 44px。
- 扫描、提交、回访共用物流式进度卡片，显示平均耗时、累计用时；扫描按环境去重计时，完成后冻结。扫描结束保持用户的展开状态。
- 日期范围包含起止日；单件、多件、件数待核对及申请状态交叉筛选。改变筛选清空勾选，全选与提交只作用于当前可见且可申请的订单。
- `after_sale_order_detail.py` 从匹配订单的 SSR 文档解析 `orderGoodsList`，逐项读取名称、规格、数量和图片；与平台 `orderGoodsSum` 独立核对。一个 SKU 数量为 2 属于多件；包装名称中的“10 piezas”不用于计算数量。
- 用 `order_package_info_list` 与全部商品的包裹关联交叉核对完整性。全部包裹取得 `signed_time` 才生成整单送达日期，取最晚一天；发货时间 `deliveryTime` 不作为签收时间。
- 日期由当前浏览器的 Intl 时区规则格式化，与平台使用的浏览器时区一致。未使用操作系统时区库替换平台规则，也不跨环境比较裸时间。
- 商品详情采集失败保留资格核验结果，件数和日期显示待核对。扫描停止后不再进入后续订单详情。
- 商品图片弹窗显示逐项名称、规格和数量；弹窗居中。提交终态会撤销对应扫描行的可申请状态与勾选，避免保留已失效选择。

## 精确原因、回执与重提保护

- `blocked` 只表示本次没有可申请包裹。只有只读核对到匹配订单的退款凭证，才显示“已有退款申请”，备注列出真实退款单、阶段、平台原始申请时间和时区。
- 兼容两种已观察到的退款 URL 参数：`refund_bill_id`、`refund_bill_id_list`；校验域名、路径订单号和参数间一致性。补查详情时还核对正文退款号，拒绝串单或冲突参数。
- 派发提交点击前进入 `verifying`（提交核验中），不计入已完成。跳转超时、退款号缺失、点击后连接异常等不能作为普通失败补提；只读补查结束后仍无法确认本次写入归属，则进入 `uncertain`（待核对）。
- 每取得一笔回执立即保留，即使后续详情失败也不丢失。凭证来源区分 `submit_redirect`、`existing`、`recovered`；已有和补查记录不伪造本次 `submittedAt`、包裹号、退款路径或操作者。
- 前端、历史详情及 Excel 共用上述状态口径；提供可展开退款凭证。旧“可能已提交过”只能标成历史原因未核实，不能凭空升级为确定原因。
- 待核对和旧版“提交后未跳转／已跳转退款页无回执”等记录排除出补提；有部分退款凭证的失败先人工核对。服务端也拦截直接输入绕过，按租户与规范化订单号保护，不因环境序号、ID、名称别名变化而失效。任务整体结果不明且缺少行回执时同样保护。
- 回执与未知状态经执行器投影、云端闭集、持久化、终态重传、历史和导出保留。已有退款单可进入现有只读回访链路，不被算作本批新增成功。

## 协议与发布顺序

- 云端迁移 `0041_after_sale_uncertain` 扩展提交行约束，接收 `verifying`、`uncertain`。`uncertainCount` 只扩展售后提交终态闭集，其他任务协议不变。
- 退款 JSON 增加来源、阶段、平台申请原文时间与时区字段；旧记录缺字段仍可读取。
- 新执行器声明 `after.sale.receipt-recovery.v1`；云端对售后写任务检查该能力，旧执行器不能继续使用缺少回执保护的提交路径。
- 发布顺序：先云端迁移及兼容接收方，再发布执行器/安装包。仅热部署前端不能带来采集和回执修复。版本号在实际发布时统一调整；本次未发布安装包。
- 回退前必须处理待核对及核验中记录。迁移拒绝把它们静默降级成可重试失败。

## 验证与限制

- 合成测试覆盖 URL 身份、多个商品及同 SKU 多件、包裹完整性、浏览器日期映射缺失、停止、核验中进度、部分回执保留、来源与操作时间、云端终态重传、历史/导出、环境别名与订单号规范化保护。
- 本地浏览器以权威 HTML/CSS 和渲染函数配合合成数据验证：29 行完整保留且容器 1320px，短表自然收缩、固定表头、筛选交集、可见全选、筛选清选、多商品详情、44px 输入区和精确退款备注。
- 隔离 PostgreSQL 18 已验证空库全量升级到 0041、回退 0040 和再次升级。SQLite 测试验证存量行保留及有未知状态时拒绝回退。
- 真机仅执行只读核对，验证多商品数量、送达时间补采及既有退款详情解析；真实订单证据保存在授权私有记录中，不提交到工程仓。
- 未执行真实退款提交，未回填历史业务数据库，未推送、部署或替换正在运行的客户端。平台 SSR/页面结构改变时保留待核对，不能据此推断无订单或已提交。
