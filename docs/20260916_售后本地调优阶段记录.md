# 售后本地调优阶段记录

用户要求先在本地修改此前记录的问题，云端继续用于真实提交测试。本轮没有部署、重启云端或本机执行器，没有操作真实扫描/退款。以下为本地阶段成果，不代表上线验收。

## 已确认口径

- 平均耗时：已实际处理的每个环境／订单耗时平均；扫描按环境去重，不能因同环境多订单重复计权。未执行的停止行及缺失耗时不作为零耗时样本。
- 多包裹送达日期：必须有完整逐包证据、全部已送达，才取最晚日期；包裹不全、日期缺失、状态未送达时均待核对。

## 本地实现

- 三表使用约20行标准高度上限（标准行64px、表头40px，最大1320px），不足时自然增高，内部滚动、表头固定，不截断数据。
- 状态条采用上方标题/说明/收起、下方停止/进度/统计布局；增加累计用时、终态冻结和实际耗时平均。扫描耗时通过执行器到云端传递，按环境去重；云端扫描/回访返回带时区的起止时间。
- 每次创建任务重置计时和进度快照，提交立即显示0/N，避免继承上轮完成状态。
- 清单新增日期范围、件数、申请状态、日期完整性筛选，以及件数列、多个缩略图和图片详情。筛选变更清空勾选；全选仅覆盖当前可申请结果；提交前核对，关闭确认不创建任务，确认时再次检查清单是否变化。
- 列表日期支持一位日及较长月份名；日期缺失增加一次有上限的同页重读，仍缺失时明确提示，不以预计送达或下单时间替代。
- 采集订单卡片明确的 Artículos 总数及全部商品图片；不以图片或包裹数量推算件数。数据缺失时待核对，旧快照兼容。

## 尚未完成的真实数据验证（发布阻断）

1. 当前真实采集尚未提供可靠的 `totalPackageCount` 和 `packageDeliveries`。日期完整性算法及筛选界面已实现，但真实数据将保守显示待核对，不能宣称日期筛选已完整可用。必须补全经过验证的整单包裹来源后才能上线该功能；仅一个可退包裹不能证明整单只有一个包裹。
2. 逐商品名称取图片已有 alt，规格和数量没有证据时保持未知，不擅自填写。完整规格、逐项数量仍需验证真实来源。平台 Artículos 总数是否包含同款多件的全部数量须用对应样例校验；未验证前不将单件／多件筛选作为真实提交决策依据。
3. 本轮没有打开真实平台环境以补这些字段，避免干扰用户云端测试。局部纯函数输入与合成数据回归不替代真机验收。
4. 未修改现有 Excel 全量导出范围或主动扩展其商品字段；该扩展仍按已记录需求另行确认。

## 验证

- 本地相关回归175项通过；云端导出与扫描端到端12项通过。其后仅修改测试样稿数据与扫描空表跨列数；生成同步及浏览器验证完成。
- 新增日期合法性、多包裹完整性、重复包裹、图片不能推断数量、隐藏订单不提交、日期与件数组合筛选、平均耗时按环境去重、累计时间冻结的回归。
- 在本地合成页面实测：多件＋截止日期筛得1单；全选后确认弹层仅含该单；扫描完成显示平均30秒/环境、累计用时并冻结；三表computed style均为1320px最大高度、auto滚动、sticky表头；无浏览器错误。
- 独立评审发现并修复两项：缺少整单包裹证据不能判日期完整；新提交不能继承旧进度快照。复核无未关闭代码阻断，评审明确不等于线上验收。
