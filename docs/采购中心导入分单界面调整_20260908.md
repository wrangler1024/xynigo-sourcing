# 采购中心导入分单界面调整

## 目标与范围

按已确认的原型，将导入分单放在采购中心二级菜单第一项，采用双卡片、三步流程、横向统计与预览表排版。页面/卡片标题 15px、按钮 12px、说明与表格内容 11px、表头与状态标签 10px、统计数字 22px，与现版采购任务/采购执行字号对齐。

真实输入仍为店小秘 xlsx、飞书共享表格链接和手动选择的工作表。输出仍为解析预览、协作表下载，以及经用户确认的飞书导入任务。此入口不创建采购任务。现有 assistant.access 授权、登录身份、云端/本机 API 路由、表头规范化和防重逻辑继续使用。

## 实现

- 修改唯一前端源 `src/purchase_tool/web/index.html`，由 `cloud/auth-service/deploy/sync_web_workspace.py` 同步云端页面。
- 控件 ID 与原导入处理器保持连接；没有复制原型的模拟接口、演示账号、示例文件或自动预填逻辑。初始状态等待用户选择真实文件。
- 状态展示随解析、目标读取、校验和导入进度更新；选择新目标会清除旧目标校验与完成状态。
- 解析、读取、校验和导入过程中锁定文件、目标表和重新开始操作，防止并发操作串批。读取导入进度失败时保留当前任务目标，并开放原有安全重试入口。
- 导入仍经过原有确认弹窗，取消不发起写入。重新开始只清空当前页面准备状态，不删除已导入数据。
- 解析结果新增 `quantityCount`，从本批全部采购明细的“需求数量”求和；预览仍最多 50 行。兼容旧接口时只在完整预览覆盖本批数据的情况下求和，否则显示“—”。
- 共享解析核心通过 `sync_procurement_import_core.py` 同步至云端，避免两套统计口径。

## 验收检查

- 整批 60 条明细、90 件时，50 行预览只含 75 件，界面仍应使用整批 90 件。
- 初始页面不得自动调用解析或导入接口。
- 校验不通过时导入按钮不可用；用户取消确认时不发起写入。
- 执行中禁止切换文件与目标；进度读取失败仍可重试同一任务。
- 完成后切换目标必须重新校验；重新开始或解析失败不保留旧成功提示。
- 本机/云端 HTML 逐字一致，完整脚本语法检查通过，页面控件 ID 无重复。

自动化验证见 `tests/test_procurement_import.py`、`tests/test_procurement_import_ui.py`、`tests/fixtures/procurement_import_ui.cjs` 与云端 `tests/test_procurement_import_cloud.py`。

纳入 v0.17.9 发布。开发验证使用合成数据，未触发真实飞书写入；日志诊断和规格匹配改动一并保留。
