# 三端协作与交接

状态：v1 草案 · 20260910。共同底线见 [AGENTS.md](../AGENTS.md)。

## 角色与资源

Codex、Cursor、ZCode 均可开发、维护、评审和在授权范围内操作服务器。每单明确开发者、独立评审者；涉及集成或发布时再明确集成/发布负责人。角色可轮换，权限不由 agent 名称决定。

开发者应自查并提交本人负责的改动。评审者优先只评审；若亲自修改实现，该部分需交另一未参与实现者复核。日常文档更正可采用轻量 diff 评审，无需额外安排第三轮仪式性复核。

一个写入者占用一个工作区。worktree 不隔离同一数据库、服务器、HubStudio 环境、端口、缓存或输出目录；使用前记录目标、操作者和预计释放条件。部署与共享库迁移同一目标串行执行。不得因自己的工作暂停，擅自取消他人的业务任务。

## 开工与交接

开工核对 Git 和最近记录；只有任务依赖线上状态时才检查线上。找不到私有记录时，继续不依赖它的本地工作，不能猜测授权、数据库版本或部署状态。

`handoff.md` 或任务交接顶部只有一处“最近核验的当前状态”。历史必须明确标日期并标为历史，不能保留多个互相竞争的“最新状态”。每个并行任务独立记录进展；总体交接由集成/发布负责人更新，不能互相覆盖下一步。

可使用以下模板，字段无关时写“不涉及”，未核验时写“待确认”：

```text
最近核验的当前状态
- 核验时间（含时区）：
- 本次范围与负责人：
- 仓库 / 分支 / HEAD / 评审范围：
- 未提交改动与归属：
- 已有授权及范围（私有记录保存原始依据）：
- 环境类别 / 已部署版本 / 核验时间：
- 构建来源 SHA / 发布 SHA / runtime ID（若涉及）：
- 验证命令与结果 / 未运行项及原因：
- 独立评审者 / 必须改闭环 / 建议改处置：
- 已完成 / 下一步 / 卡点：
- 占用资源及释放状态：
```

部署原始证据另存私有记录：环境定位、备份定位、任务状态和授权依据不原样复制到公开 handoff。普通公开代码任务可以在 PR 或任务交接中维护上述信息，不强制新增根目录 `handoff.md`。

## 评审与收口

交付评审时提供基线 SHA、候选 SHA、diff、验证结果、已知限制，以及涉及的跨仓提交。评审意见分“必须改”和“建议改”；前者关闭后才能合并或发布，后者说明采纳或暂缓理由。

开发者修复后提供新 SHA，并重跑受影响检查。评审者复核增量；修复改变设计或公共契约时扩大复核范围。CI 检查要对应最终候选，不能用旧 SHA 的成功结果证明新提交。没有触发、被跳过或只覆盖其他组件不等于通过。

分别记录“代码完成、评审通过、发布完成、业务验收完成”。本单只要求草案或本地修复时，明确实际完成层级；不声称发布，也不为尚未授权的发布反复等待。紧急例外须由 Jeff 明确本次范围、未满足检查和补审安排，不能由开发者自行宣布豁免。

## 文档权威与维护

| 内容 | 权威位置 |
|---|---|
| 每单必须遵守的规则、查阅入口 | 各仓 `AGENTS.md` |
| 本仓开发与检查命令 | 各仓 `CONTRIBUTING.md` 与实际 CI |
| 共同字段、协议兼容和发布顺序 | [生态跨仓契约](生态跨仓契约.md)及相应源码/测试 |
| 部署和发布操作顺序 | [部署与发布手册](部署与发布手册.md)；目标参数存私有运维记录 |
| 已确认长期决策及原因 | 经脱敏的决策文档；私有 `PROJECT_MEMORY.md` 可保留内部依据 |
| 当前工作进度 | 任务交接；总体状态由集成/发布负责人汇总 |

发现文档与实现冲突时记录差异，核对最近提交和裁决；源码说明当前行为，但不自动批准违反安全边界的行为。不要把未实现的规划更新成“已完成”。

普通措辞、链接、已授权实践的记录可直接维护。源码归属、授权边界、发布渠道及不兼容契约策略等重大变化先形成具体方案，经 Jeff 确认后定稿。跨仓变更更新权威正文和受影响仓库摘要/指针；不要求无关仓库重复复制全文。
