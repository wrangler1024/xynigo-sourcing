# 本地执行器设备通信 P1 实现

日期：2026-08-27
状态：本地代码与合成测试完成，未部署共享测试，未发布新安装包

## 本轮交付

P1 已形成第一个可运行纵切面：用户从云端 Web 下载执行器、生成一次性配对码，在本机完成配对；本地执行器随后只通过出站 HTTPS 长轮询连接云端。Web 能看到真实设备心跳，读取本机现有配置，并带 revision 保护保存非敏感配置。

本轮没有接入真实物流查询、建环境、打开 HubStudio 环境或 SHEIN 下单任务，也没有执行生产部署、共享测试部署、HubStudio/SHEIN 写入或飞书业务表写入。

## 通信与信任边界

```text
云端 Web 用户会话
  └─ 用户权限：设备查看 / 配对 / 撤销 / 配置读取 / 配置写入
       └─ PostgreSQL：设备、配对码摘要、任务、租约、脱敏事件
            ▲
            │ HTTPS 443，20–25 秒长轮询
            │ 独立设备 Bearer，拒绝 Cookie
            ▼
本地执行器
  ├─ Keychain / CurrentUser DPAPI：原始设备凭证
  ├─ 运行数据/executor-channel.json：非敏感设备状态
  ├─ config.json：本地配置事实源
  └─ LocalTaskCoordinator：配置与业务任务最终互斥闸门
```

云端不主动访问员工电脑端口，Web 不以 `localhost` 回环调用作为主通信路径。用户会话令牌、设备凭证和任务租约令牌三者互不替代。

## 数据模型与迁移

本地 Alembic head：`0015_executor_channel_p1`，down revision：`0014_proc_import_cloud`。

| 表 | 关键事实 |
|---|---|
| `local_executors` | 租户、所有者、平台、版本、能力、凭证摘要、最近心跳、配置摘要、Hub 状态、撤销状态 |
| `executor_pairing_codes` | 配对码摘要、5 分钟过期、单次消费、绑定后的设备 ID |
| `executor_tasks` | `config.read.v1` / `config.write.v1`、幂等键、载荷、租约摘要、状态和脱敏结果 |
| `executor_task_events` | queued/leased/started/progress/finished/uncertain 等追加事件 |

迁移已在隔离 SQLite 文件上完成 `0014 → 0015 → 0014 → 0015` 往返验证。历史全迁移链不能直接用 SQLite 验证，因为旧 `0002` 使用 SQLite 不支持的 ALTER CONSTRAINT；正式部署仍必须在 PostgreSQL 备份后执行完整升级和结构回读。

## 配置语义

`config.json` 仍是本机事实源。云端设备通道只对“设备运行配置投影”做规范 JSON SHA-256 得到 revision，避免站点、分组、采购员模板等历史业务偏好变化导致无关配置冲突。读取任务只返回设备运行与安全字段。写入任务允许：

- HubStudio Local API 端口
- 查询并发数
- 建环境并发数
- 新环境抽检数
- 查物流与建环境安全并行开关

默认采购站点、MX/US HubStudio 分组和采购员分配模板属于早期单机环境创建流程，不是设备属性。它们继续保留在旧 `config.json` 和本机环境创建页面中兼容已发布客户端，但不再由“系统管理 → 本地执行器”展示、读取或写入：站点与分组在“资源中心 → 环境创建”按任务选择，采购员分配由云端任务和本批操作决定。云端仍接受 `v0.12.6` 执行器返回的旧安全字段集合，避免升级期间读取任务失败；新的写接口拒绝这些历史业务字段。

该配置边界已于 2026-08-28 以提交 `92c11f1` 部署到共享测试云端，数据库无迁移。云端页面与写契约立即生效；设备 revision 投影和独立本机写入校验属于执行器代码，需随下一版本安装包生效。

写入需要云端最后心跳 revision 与用户提交的 `expectedRevision` 一致；设备实际执行前再次和本机实时 revision 比对。配置通过既有 `updated_config()` 校验并由 `save_config()` 原子替换。配置任务使用 `LocalTaskCoordinator.begin('config')`，不能与物流、建环境、注册等本地任务并发修改运行参数。

代理提取链接、飞书路由和任何凭证都不在本轮远程配置范围内。写入失败、revision 冲突或本地任务占用时，原配置保持不变；文件已经成功替换但 Hub 重连失败时，配置仍视为已保存，下一次心跳单独报告 Hub 离线。

## 本地安全存储与绿色包

- macOS：Keychain service `io.xynigo.sourcing.executor`，account `xynigo-device-credential`。
- Windows：CurrentUser DPAPI 文件 `%LOCALAPPDATA%/Xynigo/credentials/executor-device.bin`。
- 普通状态文件不允许出现 credential、token、password、cookie 或 authorization 字段。
- 源码入口：`python -m purchase_tool pair <配对码>`。
- macOS 绿色包：`配对本地执行器-Mac.command`。
- Windows 绿色包：`配对本地执行器.bat`。
- Windows 标准安装包：注册 `xynigo://`，开始菜单提供启动/配对/卸载；版本和用户数据分目录保存。
- macOS 标准安装包：原生 `.app + .pkg`，双击应用启动执行器，注册同一低风险 `xynigo://`；数据固定在 `~/Library/Application Support/XynigoSourcing`，首次启动可显式迁移绿色包白名单数据。
- 标准安装包一键配对：云端返回一次性码和 `pairingRequestId`，Web 通过 `xynigo://pair` 打开本机应用并只轮询该请求；设备完成首次认证长轮询后才显示在线，不再把“配对码已兑换”误判为真实心跳。
- 配对脚本属于更新器受管路径；`config.json`、查询日志和运行数据继续属于保留路径。

## 状态机与恢复

```text
queued → leased → running → succeeded / failed
   │        │         │
   │        └─ 未开始租约过期 → queued
   │
   └─ 用户取消 → cancelled

running read 租约过期  → queued（读取可安全重试）
running write 租约过期 → uncertain（写入不可自动重放）
running + 用户取消     → cancel_requested → 由设备结束或租约接管
设备撤销               → queued/leased 取消，running 转 uncertain
```

同一完成回执重复提交且结果完全相同时按幂等成功处理；内容不同则返回冲突。执行器进程内会优先重试尚未确认的完成回执，但不会把租约令牌写入普通状态文件。进程崩溃后由云端租约规则保守接管。
