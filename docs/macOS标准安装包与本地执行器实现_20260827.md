## 安装与数据边界

| 项目 | 固定值 |
|---|---|
| 应用安装位置 | `/Applications/Xynigo Sourcing.app` |
| 用户数据位置 | `~/Library/Application Support/XynigoSourcing` |
| Bundle ID / 包标识 | `icu.samforo.xynigo.sourcing` |
| 开机启动 | 不注册 |
| 系统服务 | 不安装 |
| 桌面壳 | 不引入 Electron/Tauri |
| 在线更新 | 关闭绿色包目录替换器，由后续签名安装包升级 |

`.pkg` 写入系统 `/Applications`，安装时预期由 macOS Installer 请求管理员确认。应用升级只替换应用包；`config.json`、查询日志、运行数据和导入文件均在用户数据目录，不属于安装载荷。删除应用也不会自动删除用户数据，正式卸载工具需要后续独立设计。

## 启动和协议

原生 Swift 启动器只执行两类固定动作：

1. 用户双击应用时，通过 Terminal 打开应用包内固定的 `启动本地执行器.command`。
2. 系统把 `xynigo://` 交给应用时，启动器先验证协议，再以当前用户 `0600` 临时文件交给固定的 `协议启动.command`。

云端标准包配对交互已经接通：生成配对码后返回不可猜测的 `pairingRequestId`，Web 显示“在 Mac 上打开 Xynigo 并配对”，调用 `xynigo://pair?code=...` 后每 2 秒查询这一条配对请求。配对码被兑换只表示设备身份已创建；只有该设备使用 Keychain 中的新设备凭证完成首次 HTTPS 长轮询后，Web 才显示“已配对并收到真实心跳”。60 秒内未收到心跳时页面停止等待并保留人工重试入口。

协议仍只允许：

- `xynigo://start`
- `xynigo://wake`
- `xynigo://pair?code=ABCD-EFGH`

采购、建环境、查物流、凭证传递以及任意命令执行均不是 URL 协议能力。真正业务任务仍须通过设备凭证认证的云端长轮询、租约和幂等任务通道下发。

本地执行器启动时固定：

- `XYNIGO_DATA_DIR=~/Library/Application Support/XynigoSourcing`
- `XYNIGO_INSTALL_MODE=standard`
- macOS `flock` 单实例文件为数据目录内 `executor.lock`，权限为 `0600`

## 绿色包迁移

首次双击应用且标准数据目录没有 `config.json` 或启动标记时，启动器提供“直接启动 / 迁移绿色包数据 / 取消”三个选项。迁移时用户通过系统目录选择器明确选择已解压绿色包。

迁移器必须看到源目录 `VERSION.json`，只复制以下白名单且不覆盖标准版已有文件：

- `config.json`
- `查询日志 / 日志 / logs`
- `运行数据 / data / 数据`
- `imports / 导入文件`

源目录保持只读；符号链接、磁盘根目录、无版本标记目录和源/目标相同均拒绝。迁移不是自动扫描，也不会读取其他任意目录。

## 构建链路

构建入口：

```bash
XYNIGO_RELEASE_CHANNEL=test bash 组装macOS标准安装包.sh
```

构建脚本先调用现有 `组装macOS绿色包.sh`，从更新清单选择已校验的 `macos-arm64` 不可变运行时，再完成：

1. 编译目标为 `arm64-apple-macos13.0` 的原生 Swift 启动器。
2. 生成含 `CFBundleURLTypes` 的 `Info.plist` 和 `.icns`。
3. 清除应用源目录扩展属性与真实 `._*` 文件，ad-hoc 签名并严格验证应用结构。
4. 用 `pkgbuild` 组件清单固定 bundle 不可重定位、版本检查和 upgrade 覆盖语义。
5. 用 `productbuild` 生成未签名 `.pkg`。
6. 检查应用、运行时和协议载荷存在，且不含 LaunchAgent、LaunchDaemon 或 Login Item。
7. 生成独立 JSON 元数据与 SHA-256，并强制不可发布。

`pkgutil --payload-files` 在新 macOS 上可能显示 `._*` 安装元数据记录，用于承载扩展属性；这不等于应用源目录包含 AppleDouble 文件。构建闸门检查的是进入 `pkgbuild` 前的应用源目录必须没有真实 `._*` 文件。

## 发布硬闸门

正式给采购电脑安装前仍必须完成：

1. 新版本号构建，不能用同名 `0.12.5` 替换既有 Release 资产。
2. 用 `Developer ID Application` 签名所有 Mach-O、内置运行时和 `.app`。
3. 用 `Developer ID Installer` 签名最终 `.pkg`。
4. 提交 Apple notarization、等待成功并 stapling，再离线验证 Gatekeeper。
5. 远端 macOS CI 全绿并保留构建证据。
6. 在至少一台真实 Apple Silicon 采购 Mac 验证安装、升级、首次迁移、`xynigo://start`、一次性配对、双实例阻止、断网和设备撤销。
7. 决定 Intel Mac 是否仍需支持；当前包不支持 `x86_64`。
8. 云端下载清单增加标准包但保留绿色包回退入口，经人工灰度后再调整默认下载推荐。

本次没有把 `.pkg` 安装进本机 `/Applications`，也没有上传 GitHub、修改共享测试云端或触发真实 HubStudio/飞书/SHEIN 写入。
