## 决策

### 1. 服务器与域名

| 环境 | 服务器 | 公网入口 | 用途 |
|---|---|---|---|
| 测试 | `shared-test-gz-01`（多项目共享测试服务器） | 暂保留 `https://xynigo.samforo.icu` | 开发、联调、迁移演练和脱敏测试 |
| 生产 | `xynigo-prod-gz-01` | 计划使用 `https://app.xynigo.com` | 同事正式使用和真实业务数据 |

- `shared-test-gz-01` 不得部署生产容器、生产数据库或生产密钥，Xynigo 操作不得影响该服务器上的其他测试服务。
- `xynigo-prod-gz-01` 不运行开发分支、测试任务或测试数据库。
- 两台服务器分别维护 Nginx、TLS 证书、安全组、防火墙和系统更新。
- 两台服务器对公网只开放 `80/443`；SSH 端口执行最小来源限制，PostgreSQL 和应用内部端口不得对公网开放。
- 测试环境后续如迁移到 `https://test.xynigo.com`，应先并行验证，再下线 `https://xynigo.samforo.icu`，不在本次生产上线中强制切换。

### 2. 部署目录与运行栈

| 环境 | 服务器目录 | Compose 项目 | 应用回环端口 |
|---|---|---|---|
| 测试 | `/opt/xynigo-auth-test` | 保留现有项目，后续受控规范为 `xynigo-auth-test` | `127.0.0.1:8080` |
| 生产 | `/opt/xynigo-auth-prod` | `xynigo-auth-prod` | `127.0.0.1:8080`，执行前确认端口空闲 |

由于两个环境位于不同服务器，可以使用相同的回环端口，但必须分别拥有：

- Docker Compose 项目、容器、内部网络和 PostgreSQL 数据卷；
- PostgreSQL 数据库名、用户和密码；
- `.env`、会话密钥、Cookie 名和 Cookie；
- Nginx 站点、应用日志和部署目录；
- 数据库备份目录、保留策略、异机副本和恢复记录；
- 飞书 Base、表格路由和同步状态。

不得通过复制或复用测试 PostgreSQL 数据卷建立生产环境。生产数据库必须从空库执行经过验收的 Alembic 迁移，测试数据不得进入生产库。

### 3. 飞书应用共用规则

测试与生产共用企业自建应用“小犀代采”的 App ID/App Secret，以保证同一企业成员在两个环境中的飞书身份映射一致。

飞书应用安全设置需要同时登记以下精确回调地址：

```text
https://xynigo.samforo.icu/v1/auth/feishu/callback
https://app.xynigo.com/v1/auth/feishu/callback
```

如果测试入口以后切换为 `test.xynigo.com`，应先增加新回调并完成验证，确认无误后再移除旧回调。

共用应用不等于共用业务数据：

- 测试环境只允许配置测试 Base/Table，生产环境只允许配置正式 Base/Table。
- 两个环境分别保存同一应用凭证，文件权限保持 root-only；凭证不得进入仓库、命令参数、日志或部署包。
- 测试环境必须配置飞书目标白名单或同等后端校验，防止误写正式 Base。
- 飞书应用权限和成员可用范围是两个环境共享的，不能把应用后台权限当作环境隔离边界。
- 后续接入飞书事件订阅时，使用单一事件入口并按明确规则路由和幂等处理，不允许测试、生产重复消费同一事件。

### 4. 数据与会话隔离

- 两个环境的 `tenant`、用户、角色、会话、采购单、采购分单、Outbox 和审计数据全部独立。
- 测试环境的登录 Cookie 不得被生产环境接受，生产 Cookie 也不得被测试环境接受。
- Cookie 使用 Host-only 或严格限定域名，不设置可跨测试与生产共享的宽泛 Domain。
- 测试环境中的合成采购单、账号引用和 Outbox 不得复制到生产。
- Hub 环境、买家号密码、Cookie、App Secret、访问令牌和接码 Key 不得进入普通采购业务字段。
- 生产服务器不得挂载、备份或访问测试服务器的数据库数据卷；测试服务器同样不得访问生产数据卷。

### 5. 备份、监控与服务器边界

生产环境启用前必须完成：

- 核对 `xynigo-prod-gz-01` 的操作系统、CPU、内存、磁盘、带宽、公网 IP 和 SSH 密钥绑定状态；
- 完成系统更新、SSH 密钥登录、防火墙、时区和最小权限加固；
- 部署前应用、环境文件和 PostgreSQL 完整备份方案；
- 数据库备份 SHA-256 校验和 `pg_restore` 清单校验；
- 自动每日备份、部署前备份、保留周期和至少一份异机加密副本；
- 独立恢复演练，记录恢复耗时与恢复点；
- `/healthz`、`/readyz`、磁盘空间、容器重启、数据库连接、证书到期和备份失败告警；
- 明确接受生产首期仍为单节点部署的停机风险及 RPO/RTO。

现有测试服务器上的 n8n 已于 2026-08-25 按用户明确指令停止，容器与 `n8n_n8n_data` 数据卷保留且自动重启关闭。除非再次明确授权，不恢复或删除 n8n；宝塔、FinePack Hub 和其他既有服务仍不属于生产部署变更范围，不得停止、重建或修改。

阶段 1 不修改服务器状态。若生产实例规格或磁盘不满足预算，停止执行并重新评估。

- 先由一至两名采购员灰度，再扩大正式成员范围。

## 验收标准

- 测试入口只进入现有广州测试服务器，`app.xynigo.com` 只进入 `xynigo-prod-gz-01`。
- 两个环境位于不同服务器，数据库、数据卷、网络、会话密钥、日志和备份完全独立。
- 测试写入不会出现在生产数据库或正式飞书表；生产写入不会出现在测试数据库或测试飞书表。
- 测试 Cookie 无法访问生产接口，生产 Cookie 无法访问测试接口。
- 两台服务器的 `5432` 和应用回环端口均不可从公网访问。
- 生产迁移版本与批准上线版本一致，数据库从空库创建且无测试数据。
- 生产备份可恢复、异机副本可读取、监控告警可触发。
- 测试环境和其他现有服务在生产部署过程中不受影响；n8n 保持已停止状态，不得被生产部署意外拉起或删除。

## 回滚原则

- 生产验收失败时，停止 `xynigo-prod-gz-01` 上的生产 Nginx 站点和应用容器，保留失败现场，不修改测试服务器。
