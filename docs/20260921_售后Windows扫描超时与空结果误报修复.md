# 售后 Windows 扫描超时与空结果误报修复

状态：已合并主分支、推送并部署 v0.18.11 测试工作台与双平台安装包。基线 `d543e07`，分支 `codex/after-sale-windows-scan-timeout`。

## 问题证据

v0.18.10 在一台 Windows 执行器上多次约 48 秒返回“扫描完成”，页面显示已处理 0/15、订单列表 0 行。同版 macOS 扫描同批环境得到订单。Windows 执行器日志记录数次 `HubStudio Local API 请求超时` 和一次 `匹配 Hub 环境超时`。原 45 秒总预算与单次 10 秒超时对慢速 Hub 不够宽容；扫描在环境清单匹配后才建行，异常由批次线程记录后把 running 清零，云端任务代码无条件返回成功，因此出现假“无可售后订单”。日志不足以证明具体是哪一页或 Windows 系统本身导致响应慢。

## 修复

- Hub 环境分页读取预算调整为 300 秒，单次请求最多 45 秒。只读查询遇到超时时对同页最多重试一次；其他错误不重复请求。匹配齐精确序号/ID 后仍立即停止分页；按名称匹配仍需完整查重。查询可响应停止，不无限等待。超时原因包含页号。
- 扫描在 Hub 请求前建立全部目标环境的运行行，显示“正在匹配 Hub 环境（已找到 n/N），尚未扫描订单”。查询失败或停止时，每个环境有明确失败/停止状态与原因；未开始读取订单时不冒称已扫描。
- 云端执行器完成扫描时检查环境行是否齐全、是否全为终态以及是否失败/停止；任何异常返回失败回执，保留最后的进度快照供页面展示。正常完成但没有可申请订单仍成功。部分环境已完成时页面标题明确“扫描完成（部分失败）”。
- 新增确定性回归覆盖：Hub 同页超时重试、非超时不重试、预算到期与停止、匹配进度、超时不打开环境、全部失败/部分失败/真实空订单的终态区别，以及页面轮询标题。
