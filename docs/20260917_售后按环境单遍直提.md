# 采购售后：按环境单遍直提（实现记录）

日期：20260917。需求由 Jeff 当日确认（「按环境提交兼容单遍直提，前端提示提交环境上限，直接负责代码落地」）。
候选分支 `codex/after-sale-claim-env-direct`，已 rebase 到含并行线「SHEIN 店铺授权」合并的 `origin/main`
（迁移因此由 0044 顺延为 0045，接在店铺授权的 0044 之后）。本记录描述本地开发结果，
**不代表云端或安装包已更新**。

## 1. 问题与口径变更

旧行为（v0.18.6 `4078d41` 引入）：③「按环境提交」= 先跑一遍**只读扫描**（逐环境翻全部订单、逐单读详情、
有入口的单再调 pre_info），跑完弹「核对按环境提交」清单，人工确认后才建提交 Run **第二次打开环境**逐单提交。
真机实测扫描阶段约 **55 秒/环境**，11 个环境光扫描就要 6 分钟起步，与「快速单任务操作」的设计意图不符。

新口径（本次实现）：**按环境提交 = 单遍直提**。点一次确认后直接进环境：读到带售后入口的订单就现场
核验并提交；**没有入口的环境跳过并回报原因**，不再先出全量清单、不再人工二次核对。

| 维度 | 旧（扫描→核对→提交） | 新（单遍直提） |
|---|---|---|
| 环境打开次数 | 2 次（扫描 1 + 提交 1） | **1 次** |
| 写操作前人工确认 | 扫描结果清单逐单核对 | 发起前一次性确认（写操作 + 上限提示） |
| 无入口环境 | 扫描行「暂不可申请」，不进提交 | 环境级结果 `skip` + 原因，订单行不产生 |
| 取消 | 扫描阶段取消则整批不写 | 提交 Run 取消（`/cancel`），在途单完成后停 |
| 幂等 | 扫描清单 + 提交前 pre_info | **提交前 pre_info 体检**（唯一闸门；平台侧已退包裹不可再退） |

按订单号（完整信息）的「直接提交」入口不受影响，照旧逐单核验、逐单提交。

## 3. 计数与状态口径

- **进度** = 环境（`progressCompleted` / `progressTotal` = 已完成环境 / 计划环境）。
- **成功 / 失败 / 跳过 / 停止** = 订单（与环境数解耦；success 可能 > total，这是刻意的）。
- **环境级结果**（`environments`）：`ok` 已提交、`blocked` 入口订单均不可申请、`skip` 无售后入口、
  `fail`/`login`/`inuse`/`stopped` 故障类；每行带 `entryCount` / `submittedCount` / `blockedCount` /
  `failedCount` / `note` / `errorSummary` / `durationSeconds`，落库 `after_sale_claim_runs.environment_results`。
- 整批「全部环境无入口」= `completed`（跳过不是故障，与按单提交的 `blocked` 口径一致）；环境或订单未终态
  → `uncertain`。

## 4. 兼容与发布顺序

- **老执行器不会收到直提任务**：云端在派发前按能力位拦截（409），Web 侧也要求该能力位才允许选设备；
  失败文案明确要求升级执行器。这解决了「新云端 + 老执行器」的协议不兼容问题（老执行器的桥接层不认识
  `environmentSerials` 报文）。
- **发布顺序**：先云端（含迁移 0045（并行线 0044 店铺授权已先合入 main，本迁移顺延接在其后），`docker compose build migrate` 后再 `run --rm migrate`），
  后执行器（需要新桌面包才具备能力位与本地 `claim-environments` 路由）。云端先上不影响既有四个入口。
- 按单提交的报文与哈希口径完全未变（`items` 分支的 payload 规范化与旧版一致）。

## 6. 已知限制（v1）

1. **无按单前置防护**：直提不预知订单号，`create_after_sale_claim_run` 里针对 `uncertain/verifying` 历史
   行的逐单拦截只覆盖按单提交；直提的幂等依赖提交前 pre_info 体检（平台侧已退包裹不可再退）。
   已回传过的结果行仍参与历史防护。
2. **环境级失败没有截图**：截图按订单号挂结果行，环境整体失败（如订单列表翻页失败）只有 `errorSummary` 文本。
3. **导出不含环境级结果**：`build_after_sale_claim_export` 仍只导订单行；环境级跳过只在页面与历史详情展示。
4. **uncertain 批次无法枚举未上报订单**：执行器中途死亡时，未上报订单不在请求清单里，重新发起不会被
   逐单拦截（同为按单提交的历史风险面）。
5. 单批上限 300 环境、订单行上限 2000（云端常数），超限报 422 由执行器/云端拦截。
6. 未做真机验收（需部署云端 + 新桌面包后按 §5 流程在测试机跑一单）。
