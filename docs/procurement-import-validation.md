# 导入分单校验规则

采购单按“订单号＋包裹号”分组。任一产品行出现阻断错误，该组全部明细排除出待导入计划；同一文件存在阻断错误时，整批禁止目标表校验、协作表导出和飞书写入。修正文件后重新解析，不提供绕过错误直接导入正常订单的入口。

| 阻断错误 | 示例 |
|---|---|
| 文件或模板错误 | 文件损坏、非 xlsx、超过 20 MB、缺少或重复必需表头 |
| 订单身份缺失 | 产品行缺少订单号或包裹号 |
| XYP2 备注不可用 | 整单没有有效 XYP2、JSON 损坏、结构标记截断、旧版格式 |
| 备注内容冲突 | 同单多行内容不同；一个单元格多份 XYP2 内容不同；有效块旁存在损坏块 |
| 采购数据无效 | 缺少来源 SKU、商品 ID、精准型号、有效指导价或正整数采购数量；站点/币种/明细数组无效 |
| 导出数字无效 | 订单金额或产品售价为非法数字、负数、NaN/Infinity；产品数量非正整数 |
| 商品匹配不明确 | 无法匹配来源 SKU，或多个候选无法按完整规格区分；不再按行顺序或剩余行猜测关联 |
| 同单数据矛盾 | 同一组内店铺、订单金额、币种或 CURP 不一致 |

以下情况只警告：店小秘销售数量与 XYP2 采购数量不同（采购数量仍取 XYP2）；一个单元格重复相同的 XYP2（只解析一份）；同单某产品行无 XYP2，但其他行存在一致有效备注（使用订单级备注）。同一份备注正常重复在多条产品行上不产生重复警告。JSON 空白和对象键顺序差异不会被当作内容冲突。

目标表核心字段缺失、权限/连接失败、解析计划过期、历史订单明细冲突等原有检查继续有效。缺少图片的处理仍属于后续图片同步流程，不属于本次备注阻断错误分级。

页面区分“校验通过订单数”和“失败订单数”，校验通过不代表已写入。无法识别订单身份或读取文件时，不推测订单总数。错误与警告均带订单号、包裹号、Excel 行号、字段、错误码及说明；界面每页 50 项，可下载完整 CSV，接口和下载不再截断前 100/20 项。文件级错误使用第 1 行或“文件级”定位，不伪造订单号。

全部订单失败时，云端保持 HTTP 422，不创建可写入计划；响应 `detail.diagnostics` 提供完整清单。部分通过时返回诊断计划，`canImport=false`。服务端在启动任务和工作线程写入前再次检查计划，防止旧已校验计划或直接调用接口绕过校验。

回归材料使用合成数据：`tests/test_procurement_import_validation.py`、`tests/fixtures/procurement_import_ui.cjs`、`cloud/auth-service/tests/test_procurement_import_cloud.py`。本机解析器及 HTML 为源文件，修改后通过 `sync_procurement_import_core.py` 和 `sync_web_workspace.py` 同步云端副本。
