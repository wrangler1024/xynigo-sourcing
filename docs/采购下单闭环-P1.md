状态：后端第一纵切面和迁移已部署到共享测试云端；前端“快捷绑定资源并下单”已在本地接入安全资源查询、创建下单尝试和开始结算，并通过隔离浏览器合成回归。当前 8767 进程尚未加载该前端/本地代理增量，真实 HubStudio 环境副作用和 SHEIN 下单仍未接入。飞书仅开放另行授权的建环境/物流结果测试表同步。

## 目标与边界

本阶段把采购执行从旧测试分单推进为服务端事实状态机：

```text
采购明细认领
  → 下单尝试与数量占用
  → 开始结算
  → 付款成功 / 失败 / 结果不确定
  → 正式采购批次或资源清理
  → 物流回填
  → 明细完成或异常
```

本阶段只实现 PostgreSQL 事务、API、审计和本地安全代理。任何 API 调用都不会直接创建 Hub 环境、登录买家号、提交 SHEIN 订单、付款、删除环境或写飞书。

## 领域模型

迁移 `0008_checkout_flow` 与 `0009_buyer_account_resource` 新增：

- `buyer_accounts`：仅保存安全引用、脱敏标签、站点、可用/凭证状态、当前尝试和来源快照；不保存账号、密码、Cookie 或 Token。
- `checkout_attempts`：付款前可修改的下单尝试，包含幂等键、版本号、资源状态和待补偿终态。
- `checkout_attempt_lines`：一次尝试占用的采购明细与数量。
- `purchase_batches`：付款成功后生成的正式采购批次，保存平台单号、实付、优惠和成功资源快照。
- `purchase_batch_lines`：正式批次实际采购的明细与数量。
- `supplier_shipments`：正式批次的包裹、物流商、物流单号和状态。

采购单详情同时返回每行的 `requiredQty`、`purchasedQty`、`reservedQty`、`remainingQty`，并返回 `checkoutAttempts` 与 `purchaseBatches`。

## 状态规则

### 下单尝试

- `planning`：已占用数量，尚未完整绑定资源。
- `ready`：数量和资源已绑定，可以开始结算。
- `checkout`：已进入真实结算阶段。
- `cleanup_pending`：已登录环境发生失败或主动放弃，等待确认删除环境。
- `manual_review`：付款结果不确定、环境删除失败或资源异常，继续占用数量。
- `paid`：付款成功，已经原子生成正式采购批次。
- `failed` / `abandoned`：补偿完成的终态，释放尝试数量。

非终态尝试会占用数量；付款成功的正式批次计入已采购数量。创建和修改尝试时，服务端在行锁内校验“需求数量 - 已采购数量 - 其他尝试占用数量”，拒绝超买。

### 资源

- 同一租户内，同一个 Hub 环境或买家号只能被一个非终态尝试占用；业务校验之外还有 PostgreSQL/SQLite 部分唯一索引防竞态。
- 下单尝试必须引用云端 `buyerAccountId`；客户端提交的资源 ID 会在行锁内解析为规范安全引用和脱敏标签，不能用自由文本伪造买家号。
- 付款失败或主动放弃且已经登录环境时，尝试必须进入 `cleanup_pending`；只有环境清理确认成功后才释放数量。
- 环境删除失败时进入 `manual_review`，不得自动释放数量或资源。
- 付款成功后，Hub 环境和买家号快照进入正式批次。成功资源在复用规则确认前采取保守锁定，新的尝试一律拒绝复用。
- API 只接受安全资源引用和展示标签，不接受密码、Cookie、Token、邮箱账号或其他凭证。

### 正式批次与物流

- 付款成功在同一事务内生成一个正式批次和批次明细，并把采购明细推进为 `ordered`。
- 写入任一包裹后，批次进入 `tracking`；全部包裹送达后进入 `completed`；任一包裹异常时进入 `exception`。
- 明细状态由所有相关正式批次统一重算，支持部分采购和多批跟单。

## API

所有写接口要求 `procurement.execution.manage`，且只能操作本人认领的明细、本人创建的尝试或本人采购的批次。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/procurement/orders/{orderId}/checkout-attempts` | 创建下单尝试并占用数量 |
| POST | `/v1/procurement/checkout-attempts/{attemptId}/revise` | 结算前修改组合、数量或资源 |
| POST | `/v1/procurement/checkout-attempts/{attemptId}/begin` | 标记开始结算 |
| POST | `/v1/procurement/checkout-attempts/{attemptId}/abandon` | 主动放弃；已登录环境转清理流程 |
| POST | `/v1/procurement/checkout-attempts/{attemptId}/payment-result` | 记录成功、失败或不确定的付款结果 |
| POST | `/v1/procurement/checkout-attempts/{attemptId}/cleanup-result` | 记录环境删除与买家号处理结果 |
| POST | `/v1/procurement/purchase-batches/{batchId}/shipments` | 幂等新增或更新物流包裹 |

资源准备接口：`GET /v1/resources/buyer-accounts` 返回可筛选的脱敏资源列表；`PUT /v1/resources/buyer-accounts/snapshot` 只接受无凭证快照，并要求 `resource.buyer.import`。

本地回环代理只放行以上固定 UUID 路径和 POST 方法；浏览器仍不接触云端 Bearer 会话。

## 幂等、并发与审计

- 创建尝试使用租户级 `idempotencyKey + request_hash`；相同请求返回 `unchanged=true`，同键不同内容返回 409。
- 尝试操作使用 `expectedVersion`，组合修改额外使用采购单 `expectedExecutionRevision`。
- 物流使用 `shipmentKey + expectedVersion`；相同内容重复提交不增加版本。
- 数量校验、状态推进、正式批次、采购明细状态和 Outbox 在一个数据库事务内提交。
- 审计只记录状态、版本、计数和结果类型；资源引用、买家号标签、平台订单号、物流单号、金额明细和失败原因正文不进入审计详情。
