# Xynigo 日志中心接口（P0）

日期：2026-08-26

状态：业务操作日志 P0 已在本地完成；系统运行/错误日志 P1 也已使用独立表、统一服务、云端只读 API、本机安全代理和 Web 列表/详情完成首期开发。两批日志均尚未部署测试或生产环境。系统日志详细契约见 [`系统运行日志接口-P1.md`](系统运行日志接口-P1.md)。

## 目标与边界

业务操作日志由云端后端在业务结果处追加，前端按钮点击不是日志事实源。统一入口为 `BusinessLogService`，现有 `_add_audit` 只保留为兼容适配器并委托该服务，模块不得直接创建、更新或删除 `AuditEvent`。

每条结构化日志包含：

- `tenantId`；
- 操作人 ID、姓名快照和角色快照；
- 模块、操作类型；
- 业务对象类型、内部 ID 和安全业务单号；
- 结果、失败原因、字段级变更摘要；
- 来源、客户端版本；
- `requestId`、`traceId`；
- 操作时间。

原有 `action/result/details` 字段继续保留，保证既有登录、管理员和采购审计测试兼容。新增 `category` 预留 `business_operation`、`security`、`system_runtime` 和 `system_error` 统一分类；日志中心 P0 只查询 `business_operation`。

## 数据库迁移

- `0005_business_operation_logs_p0`：扩展 `audit_events`，回填历史 action、模块、结果口径、request/trace、操作人姓名和迁移时角色快照，并增加租户、分类、操作人、模块、业务单号、操作类型、requestId、traceId 索引。
- 采购运营归属迁移使用 `0006_purchase_operator`，直接承接已部署的 `0004_procurement_execution_test`；日志迁移 `0005_business_operation_logs_p0` 以 `0006` 为父迁移。编号来自并行开发批次，实际依赖顺序以 Alembic 元数据为准，当前只有一个本地 head。
- 共享测试库已单独部署到 `0006_purchase_operator`；本批日志迁移没有部署，生产数据库未修改。
- `0007_system_runtime_logs_p1`：在业务审计表之外创建独立的系统运行/错误日志表；当前完整本地 head 为 `0007`。

## 接口清单

| 用途 | Web 同源接口 | 云端接口 |
|---|---|---|
| 业务日志列表 | `GET /api/business-logs` | `GET /v1/business-logs` |
| 业务日志详情 | `GET /api/business-logs/{businessLogId}` | `GET /v1/business-logs/{businessLogId}` |
| 系统日志列表 | `GET /api/system-logs` | `GET /v1/system-logs` |
| 系统日志详情 | `GET /api/system-logs/{systemLogId}` | `GET /v1/system-logs/{systemLogId}` |

本机代理只允许列表路径和 UUID 详情路径，只允许 GET；外部 URL、路径穿越、管理路径和写方法均不开放。Bearer 会话继续只保存在本机系统安全存储。

## 列表筛选

| 参数 | 说明 |
|---|---|
| `startTime` / `endTime` | ISO-8601 时间范围；开始时间不得晚于结束时间 |
| `module` | 模块代码，如 `procurement`、`system` |
| `operator` | 操作人姓名或用户 UUID |
| `result` | `success`、`validation_failed`、`permission_denied`、`business_conflict`、`not_found`、`external_service_failed`、`failure` |
| `businessNo` | 安全业务单号或内部对象 ID 关键词 |
| `operationType` | 操作类型关键词 |
| `requestId` | 同时匹配 requestId 和 traceId |
| `page` / `pageSize` | 页码和每页数量；每页最多 200 条 |

响应 `data.scope` 为 `self` 或 `tenant`。列表返回结构化摘要，详情额外返回已经统一脱敏的 `details`。

## 权限与租户隔离

- 所有查询固定使用当前会话的 `tenant_id`，请求不能传入或切换租户。
- 具备 `system.audit.read` 的主管、管理员或超级管理员读取当前租户范围。
- 其他已登录成员只读取 `actor_user_id=本人` 的日志；不能通过 operator 筛选扩大范围。
- 详情重复执行相同范围条件；其他租户或范围外日志统一返回 `404 business_log_not_found`。
- 当前尚无部门/团队数据范围模型。P0 采用保守规则“审计权限=本租户、无审计权限=本人”；后续数据范围模型落地后再细分主管的部门或团队范围。

日志接口没有 POST、PUT、PATCH、DELETE；业务用户不能编辑或删除日志。数据库运维保留策略不属于业务 API。

## 脱敏规则

日志服务递归限制结构深度、项目数量和文本长度，并对敏感字段名统一替换为 `[REDACTED]`。禁止保存：

- 密码、Cookie、Token、API Key、Secret、Authorization；
- 飞书 Open ID / Union ID；
- 完整电话、详细地址、邮编；
- 完整买家号凭证、代理账号密码；
- URL 查询参数和片段。

邮箱型账号只保留首字符和域名掩码。变更摘要只保存字段名、安全状态、版本和数量，不保存字段原始敏感值。Pydantic 422 响应也删除原始 `input`，避免非法请求把敏感内容回显或写日志。

## requestId / traceId

云端接收格式安全的 `X-Request-ID`、`X-Trace-ID`，非法或缺失时后端生成；响应回传两个 ID。本机云端客户端统一发送来源、客户端版本、requestId 和 traceId。业务日志使用这两个字段串联前端、本机代理和云端业务结果。
