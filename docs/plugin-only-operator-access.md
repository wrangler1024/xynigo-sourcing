# 运营提单插件最小权限

系统开发期间，普通运营仅使用店小秘提单插件，Xynigo 网页系统只对指定运营主管开放内测。

“运营提单（插件专用）”自定义角色只配置以下三项：

| 权限 | 用途 |
|---|---|
| `procurement.request.read` | 在插件当前订单页读取本人草稿或同组织已提交采购单，恢复或核对提单内容 |
| `procurement.request.save` | 保存本人采购草稿 |
| `procurement.request.submit` | 首次提单或按最新版本修订同组织已提交单；修改仍受认领/执行状态约束 |

成员仍需管理员批准为“已启用”。使用插件的独立飞书登录即可，不要求先登录 Xynigo 网页，也不需要安装本地采购执行器。

仅持有上述权限或其中子集的成员，属于插件专用身份：网页 OAuth 不签发新工作台 Cookie；已存在的会话在页面初始化及权限刷新时锁定工作台；采购工作台接口拒绝访问。未提交草稿保持本人范围。v0.17.17 起，具备对应权限的账号可按精确订单键读取和修订同组织已提交采购单；不能跨组织读取，不开放订单列表或采购执行权限。

修订须使用提单助手 v0.12.8 及以上，带上打开明细时的版本号；版本已变化时返回冲突，要求重新读取核对。相同内容的重试不增加版本，缺少版本号的旧客户端可首次提单但不能直接修订。原提交人与首次提交时间保留，最近修改人及审计记录使用实际登录身份。认领、拆分和采购执行后的修订保护保持不变。

不向普通运营授予工作台、采购中心、小犀助手、导入分单、采购执行、资源、设备或系统管理权限。多个角色的权限会合并，分配前必须检查普通运营是否还持有管理员或其他业务角色，不能仅叠加新角色后认为旧权限已撤销。

主管另建“运营主管内测”角色。需要采购任务测试时，至少配置 `procurement.access` 与 `procurement.request.read`；需要提单时配置保存、提交权限；需要导入分单时单独配置 `assistant.access`。主管名单须明确，不能按职位名称自动推断现有账号。

纳入 v0.17.10 发布，使用已有权限码，无新增数据库迁移或权限目录项。云端及桌面执行器更新后启用插件与工作台的访问隔离。管理员先创建自定义角色，再按审核名单分配成员；角色配置不自动批准或启用账号。采购外包使用共用协作表的现有权限，本版不增加其订单范围限制。

回归入口：`cloud/auth-service/tests/test_plugin_access.py`、`tests/fixtures/plugin_access_ui.cjs`、`tests/test_plugin_access_ui.py`。测试覆盖插件登录和本人提单、网页登录拒绝、旧 Cookie 的访问限制、其他成员订单保护、主管入口及导入权限边界。
