## 3. 接口契约（全部 `assistant.access`，无新权限码）

- `POST /v1/after-sale/scan` →202 `{taskId,status,executorId}`；只建任务不建 Run。
- `GET /v1/after-sale/scan/{task_id}` →`{taskId,status,executorId,summary:{rows,totalCount,claimableCount},lastRuns}`；**运行中也带 summary**（部分行）。
- `POST /v1/after-sale/scan/{task_id}/cancel`（无 body）→ 同形状。
- `POST /v1/operation-runs/after-sale-claim` →202 `<快照>`；幂等键同 key 同 payload 复用原 Run、不同 payload 409；任务 payload `{runId,runKey,browserMode,items}`。
- `GET /v1/operation-runs/after-sale-claim/{run_id}` / `/latest` → 快照 / null。
- `POST /v1/operation-runs/after-sale-claim/{run_id}/cancel` → 快照。
- **快照为扁平键**（逐键镜像 `store_finance_snapshot()`）：`runId,status,phase,browserMode,progressCompleted,progressTotal,totalCount,successCount,failedCount,skippedCount,stoppedCount,stopRequested,startedAt,completedAt,rows[]`。

## 5. 需要留意的实现决策（评审重点）

1. **退款路径固定「原路退回」**：页面默认是 SHEIN 钱包；界面单选项与提交报文的 `path` 不是同一套取值（映射 `{1:2,2:3,3:1}`），原路退回＝`path:3`。业务口径变化需改 `REFUND_PATH_LABEL`。
2. **已提交过不可勾选**：`canPick = orderNo && claimable && status==='ok'`，这是幂等第一道闸门。
3. **skipped 与 failed 分开统计**：`blocked/skip/empty` 归 skipped，避免幂等重跑把整批误报失败。
4. **云端主动偏差 4 项**（为满足前端与本地投影，可回退但会掉功能）：
   - `executor_tasks` 新增 `progress_summary JSON` 列——扫描不建 Run，但前端要求运行中也有部分行；回退则运行中 rows 恒空。
   - Run 表新增 `skipped_count`/`stopped_count`——本地终态 summary 会回报，否则丢两个计数。
   - 提交进度行额外接纳 `packageCount`——本地扫描/提交共用字段清单；不接纳则真机提交进度 422。
   - `BUSINESS_RESULT_KEYS` 增加 `skippedCount`——否则提交终态回执 422。

**流程（两段式，0.18.0 就是这么发的）**：
